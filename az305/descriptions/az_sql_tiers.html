02 間違えやすいポイント集

落とし穴 #1

「Managed Instance には Basic / Standard / Premium がある」→ ない

MI は vCore モデルの General Purpose と Business Critical のみです。DTU モデルは MI に存在しません。

✅ MI = General Purpose または Business Critical（vCoreのみ）
❌ Basic/Standard/Premium MI — 存在しない。これを選んだら即不正解
落とし穴 #2

「Elastic Pool に Hyperscale がある」→ ない

Hyperscale は分散ストレージアーキテクチャのため、Pool でのリソース共有と互換性がありません。Elastic Pool は Basic / Standard / Premium / GP / BC のみです。

✅ Elastic Pool = Basic / Standard / Premium / General Purpose / Business Critical
❌ Hyperscale Elastic Pool — 存在しない
落とし穴 #3

「Azure Hybrid Benefit は DTU モデルにも使える」→ 使えない

Azure Hybrid Benefit（既存 SQL Server / Windows Server ライセンスを Azure で活用してコスト削減する仕組み）は vCore モデルのみです。

✅ Hybrid Benefit = vCore モデル（GP / Hyperscale / BC）に適用可能。最大55%削減
❌ DTUモデル（Basic/Standard/Premium）には Hybrid Benefit 適用不可
落とし穴 #4

「GP は Business Critical の廉価版で機能が少ない」→ 大半の機能は同じ

GP と BC の主な違いは「ストレージ種類（リモート vs ローカルSSD）」「フェイルオーバー時間（20秒 vs 数秒）」「In-Memory OLTP」「読み取りレプリカ」です。SQL Server の機能面での差は少なく、主にパフォーマンス・可用性の差です。

✅ GP と BC の違い: ストレージ速度・フェイルオーバー時間・In-Memory・読み取りレプリカ

デプロイモデル選択 — SQL Agent が必要

オンプレミスのSQL Server 2019では、SQL Server Agentで夜間バッチジョブを多数実行しています。Azureに移行後もこの構成を維持する必要があります。最適なAzureサービスはどれですか？

  • A. Azure SQL Database Single Database (General Purpose)
  • B. Azure SQL Database Elastic Pool (Standard)
  • C. Azure SQL Managed Instance (General Purpose)
  • D. SQL Server on Azure VM
✅ 正解: C — Azure SQL Managed Instance (General Purpose)

SQL Server Agent は Azure SQL Database（Single / Pool）では非対応です。SQL MI では SQL Server Agent が完全に対応しています。

なぜDは不正解か: SQL on VM でも Agent は動きますが、OS管理も必要になります。要件に「OS制御が必要」はないため、フル PaaS の MI が最適です。
なぜABは不正解か: SQL Database（Single/Pool）は SQL Server Agent に非対応です。Azure Functions や Elastic Jobs で代替が必要になります。
2

サービスティア — In-Memory OLTP

オンライン小売のトランザクション処理システムで、ピーク時に毎秒10,000件以上のトランザクションを処理する必要があります。In-Memory OLTPを使用してパフォーマンスを最大化したい場合、Azure SQL Database のどのサービスティアが適切ですか？

  • A. Standard (S4)
  • B. General Purpose (8 vCore)
  • C. Business Critical (8 vCore)
  • D. Hyperscale (8 vCore)
✅ 正解: C — Business Critical

In-Memory OLTPが使えるのは vCore モデルでは Business Critical のみ、DTU モデルでは Premium のみです。General Purpose と Hyperscale は In-Memory OLTP に非対応です。

さらに BC はローカル NVMe SSD を使用するため、高 IOPS ワークロードに最適です。

なぜBは不正解か: General Purpose は In-Memory OLTP 非対応。
なぜDは不正解か: Hyperscale は In-Memory OLTP 非対応。大容量DBや読み取りスケールアウトが得意。
3

Elastic Pool — SaaS マルチテナント

SaaS アプリケーションで、1,000社のテナントそれぞれに独立したデータベースを提供しています。各テナントのアクティブ時間帯は業種によって異なり（小売は夜間、金融は日中等）、平均使用率は低いです。コストを最適化するために最も適切な構成はどれですか？

  • A. Standard S2 の Single Database を 1,000 個作成する
  • B. Standard の Elastic Pool を作成し、1,000 個の DB をプールに追加する
  • C. Hyperscale の Single Database を 1,000 個作成する
  • D. Managed Instance を作成し、すべてのテナントのデータを1つのインスタンスに格納する
✅ 正解: B — Elastic Pool

「ピーク時間帯がバラバラ」「平均使用率が低い」「多数のDB（1,000個）」という条件は Elastic Pool のコスト効果が最大になるケースです。プールのリソースをテナントが時差で共有することで、1,000個×専用リソースより大幅にコスト削減できます。

なぜAは不正解か: 各DBに専用リソースを持つため、平均使用率が低くてもリソースを確保し続けます。Elastic Poolの5〜10倍のコストになります。
なぜDは不正解か: MI はインスタンス単位の課金で高コスト。また全テナントを1インスタンスに入れるとデータ分離が弱まります。
4

Hyperscale の使いどき

電子商取引の注文履歴データベースが急成長しており、現在50TBになっています。今後数年で100TBを超える見込みです。また、レポート生成のために読み取りクエリを大量に実行する必要があります。最適なサービスティアはどれですか？

  • A. Business Critical (32 vCore)
  • B. General Purpose (32 vCore)
  • C. Hyperscale (32 vCore)
  • D. SQL Managed Instance (General Purpose)
✅ 正解: C — Hyperscale

「50TB → 100TB超の超大規模DB」「読み取りを大量にスケールアウト」という要件は Hyperscale の典型的なユースケースです。
Hyperscale は最大100TBの自動拡張ストレージとNamed Replicaで最大30個の読み取りレプリカを提供します。

なぜAは不正解か: Business Critical は最大4TBのストレージ制限があり、50TBのDBを収容できません。
なぜBは不正解か: General Purpose も最大4TBのストレージ制限があります。
なぜDは不正解か: SQL MI GP も最大16TBです（Hyperscaleなし）。50TBは収容できません。
5

コスト最適化 — Azure Hybrid Benefit

あなたの会社は SQL Server Enterprise のライセンスをソフトウェアアシュアランス付きで保有しています。Azure SQL Database に移行してコストを最小化したいと考えています。Azure Hybrid Benefit を適用できるサービスティアはどれですか？

  • A. Standard (S4)
  • B. Premium (P1)
  • C. General Purpose (4 vCore)
  • D. Free Tier (1 vCore)
✅ 正解: C — General Purpose (vCoreモデル)

Azure Hybrid Benefit（AHB）は vCoreモデル（GP / Hyperscale / BC）にのみ適用可能です。DTUモデル（Basic / Standard / Premium）には適用できません。また Free Tier にも適用不可です。

AHB を適用すると SQL Server のライセンス費用をカバーでき、vCore モデルのコストを 最大55%削減できます。

なぜABは不正解か: Standard / Premium は DTU モデルで、AHB の適用対象外です。
