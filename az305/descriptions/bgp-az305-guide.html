BGP（Border Gateway Protocol）完全解説

AZ-305 で問われる BGP の基礎から Azure での実装・試験頻出ポイントまで、具体例と図解で徹底解説します。

① BGP とは何か ─ 一言で理解する

🔑 BGP（Border Gateway Protocol）とは、インターネット上で「どのネットワーク（AS）を経由すればどこに到達できるか」を隣接ルーターと交換し合うルーティングプロトコルです。

Azure では VPN Gateway・ExpressRoute Gateway・Virtual WAN が BGP をサポートしており、オンプレミスと Azure 間で動的なルート交換を行います。静的ルートを手動で管理する代わりに、BGP が自動でルートを学習・伝播します。

📖 BGP の重要用語

用語意味Azure での具体例
AS（Autonomous System） 同一の管理下にあるネットワークの集合。BGP ではネットワーク同士の「組織単位」 Azure は AS 65515（デフォルト）。オンプレミスは任意の AS 番号（例：65001）
AS 番号（ASN） AS を識別する番号。1〜65535（16ビット）または大きな32ビット値 プライベート AS 番号：64512〜65534。Azure は 65515 を予約。65515 はオンプレミスで使用不可
BGP ピア（Peer） BGP でルート情報を交換する相手のルーター。「ネイバー」とも呼ぶ VPN Gateway の BGP ピアアドレス（例：169.254.21.1）がオンプレミスルーターの接続先
eBGP / iBGP eBGP：異なる AS 間の BGP。iBGP：同一 AS 内の BGP Azure ↔ オンプレミスは eBGP。Azure 内部の冗長化は iBGP
BGP ルート（プレフィックス） BGP が広告するネットワークアドレス（CIDR 表記） Azure VNET の 10.0.0.0/16 をオンプレミスに広告、オンプレミスの 192.168.0.0/16 を Azure に広告
BGP ピアリング IP BGP セッションを確立するためのアドレス（TCP 179 番ポート） VPN Gateway では APIPAアドレス（169.254.x.x）または カスタム IP を使用

② Azure で BGP が使われる場所

🔒 VPN Gateway

  • サイト間 VPN（S2S）で BGP を有効化可能
  • BGP 有効時：動的ルート交換
  • BGP 無効時：静的ルート設定が必要
  • SKU：VpnGw1 以上で対応
  • アクティブ/アクティブ構成で必須

⚡ ExpressRoute Gateway

  • ExpressRoute は BGP が必須（常に有効）
  • プロバイダーの Edge ルーターと BGP ピアを確立
  • Microsoft Peering / Private Peering で別々の BGP セッション
  • AS 番号は Microsoft 側が管理

🌐 Azure Virtual WAN

  • Virtual Hub が BGP ルーターとして機能
  • ブランチサイト間のルート自動伝播
  • NVA（ネットワーク仮想アプライアンス）との BGP ピアリング
  • カスタム BGP アドレス空間設定可能

⚠️ 試験頻出：BGP 有効時の「アドレス空間」の設定変化
  • BGP 無効（静的）：ローカルネットワーク GW のアドレス空間にオンプレミスの全サブネット（例：192.168.0.0/16）を手動で列挙する必要がある

⚠️ 試験頻出：ExpressRoute の BGP 特有の注意点
  • ExpressRoute の冗長性：プロバイダーの 2 つの物理接続それぞれに BGP セッションを確立（最低 2 BGP セッションが標準）

  • ExpressRoute Global Reach：BGP を使って複数のオンプレミス拠点を Azure 経由で相互接続できる
  • ExpressRoute と VPN の共存：フェールオーバー構成でも BGP が経路切り替えを担う

⑤ 静的ルート vs BGP 徹底比較

アクティブ/アクティブ GW 非推奨（経路切り替えが困難） 推奨・組み合わせて使う

📌 試験での判断基準
  • 「ルートを自動的に学習・伝播したい」→ BGP
  • 「オンプレミスのサブネットが頻繁に変わる」→ BGP（静的だと毎回 Azure 側を更新）
  • 「高可用性・フェールオーバーが必要」→ BGP + アクティブ/アクティブ
  • 「ExpressRoute を使う」→ BGP は必須（選択肢なし）
  • 「小規模・シンプル・変更が少ない」→ 静的ルートで十分

⑥ 試験頻出問題と解説

Q1. オンプレミスに複数の支社ネットワークがあり、今後もサブネットが追加される予定です。Azure との VPN 接続でルート管理の手間を最小化するには？
A. 各サブネットを静的ルートとしてローカルネットワーク GW に手動追加する
B. VPN Gateway で BGP を有効化し、オンプレミスルーターと BGP ピアリングを確立する ✅
C. ローカルネットワーク GW のアドレス空間に 0.0.0.0/0 を設定する
D. Azure Route Server を使って静的ルートを配布する
解説：BGP を有効化することで、オンプレミスで新しいサブネットが追加されても Azure 側の設定変更なしに自動でルートが伝播されます。静的ルートでは毎回 Azure 側を更新する必要があり、管理コストが高くなります。
Q2. Azure VPN Gateway で BGP を構成する際、Azure 側のデフォルト AS 番号はいくつですか？また、オンプレミス側で使用できない AS 番号は？
A. Azure デフォルト ASN：65001、オンプレミス禁止：65535
B. Azure デフォルト ASN：65515、オンプレミス禁止：65515・8074・8075・12076 ✅
C. Azure デフォルト ASN：65000、オンプレミス禁止：65000
D. Azure デフォルト ASN：1234、制限なし
解説：Azure VPN Gateway のデフォルト ASN は 65515。オンプレミス側では 65515（Azure 予約）・8074・8075（Azure 内部利用）・12076（ExpressRoute 用）は使用できません。これらは試験でそのまま出題されます。
Q3. ExpressRoute において BGP はどのように扱われますか？
A. 任意で有効化できる（デフォルトは無効）
B. Private Peering にのみ使用される
C. 必須。すべての ExpressRoute 接続で BGP が使用される ✅
D. Premium アドオン時のみ利用可能
解説：ExpressRoute では BGP は必須コンポーネントです。オプションではなく、Private Peering・Microsoft Peering の両方で BGP セッションが確立されます。VPN Gateway と異なり有効/無効の選択肢はありません。
Q4. VPN Gateway のアクティブ/アクティブ構成を使う場合、BGP の役割は何ですか？
A. BGP は不要。アクティブ/アクティブは静的ルートで動作する
B. BGP は片方のインスタンスにのみ設定する
C. BGP が複数のトンネル経由でルートを学習し、障害時に自動でトラフィックを切り替える ✅
D. BGP はアクティブ/アクティブでは使用できない
解説：アクティブ/アクティブ構成では 2 つの GW インスタンスがそれぞれオンプレミスと BGP セッションを確立します。一方のトンネルや GW インスタンスに障害が発生しても、BGP が残りの経路でルーティングを継続し、ダウンタイムを最小化します。
Q5. BGP を使った VPN 接続でオンプレミスのサブネットを Azure に広告したい場合、ローカルネットワーク ゲートウェイの「アドレス空間」に設定すべき内容は？
A. オンプレミスの全サブネット（例：192.168.0.0/16, 192.168.1.0/24 など）を列挙する
B. BGP ピア IP アドレス（/32）のみを設定する。サブネットは BGP が自動で広告する ✅
C. 0.0.0.0/0 を設定してすべてのルートを Azure 経由にする
D. アドレス空間は空欄のままでよい
解説：BGP 有効時、ローカルネットワーク GW のアドレス空間には BGP ピア IP（例：10.100.1.1/32）のみを設定します。実際のサブネット情報は BGP プロトコルが自動的に交換・広告するため、手動での列挙は不要です。これが BGP の最大の利点のひとつです。

⑦ 間違いやすいポイント 総まとめ

間違いやすいポイント正しい理解
「Azure の BGP AS 番号は自由に決められる」 65515・8074・8075・12076 は使用禁止。カスタム設定は可能だがこれらは除外
「ExpressRoute は BGP を任意で使える」 ExpressRoute は BGP が必須。無効化のオプションは存在しない
「BGP 有効時もローカルネットワーク GW にサブネットを列挙する」 BGP 有効時は BGP ピア IP（/32）のみでよい。サブネット列挙は静的ルートの場合のみ
「Basic SKU の VPN Gateway でも BGP が使える」 BGP は VpnGw1 以上のSKUが必要。Basic SKU では BGP 非対応
「BGP を後から有効化できる」 VPN Gateway の BGP 設定は作成時に設定。後から変更するにはゲートウェイの再作成が必要
「Microsoft Peering はプライベート AS 番号でよい」 Microsoft Peering はパブリック AS 番号が必要。Private Peering はプライベート AS 可
「Azure Route Server と VPN Gateway の BGP は同じもの」 別サービス。Route Server は VNET 内の NVA と BGP ピアリングして VNET のルートテーブルを更新する
「BGP を使えばルートが即座に反映される」 BGP のコンバージェンスには数秒〜数分かかる場合がある。リアルタイム性には限界がある
「アクティブ/スタンバイ GW でも BGP は有効に働く」 有効だが効果は限定的。BGP の真価はアクティブ/アクティブ構成で発揮される
📌 AZ-305 BGP 最重要まとめ
  • BGP = 動的ルーティング：オンプレミスのルートを自動学習・伝播。静的ルートの手動管理から解放される
  • VPN Gateway：BGP はオプション（作成時に有効化）。デフォルト ASN は 65515
  • ExpressRoute：BGP は必須。Private Peering と Microsoft Peering でそれぞれ別の BGP セッション
  • アクティブ/アクティブ：BGP と組み合わせて高可用性を実現。障害時に自動経路切り替え
  • BGP 有効時のローカル GW：アドレス空間は BGP ピア IP（/32）のみ。サブネットは不要
  • 禁止 ASN：65515・8074・8075・12076 はオンプレミス側で使用不可
