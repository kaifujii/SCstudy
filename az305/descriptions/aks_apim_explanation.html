Azure API Management (APIM) — 内部モード (Internal VNet Integration)

APIM を 内部モード（Internal） で仮想ネットワークに統合することで、3つの要件をすべて単一サービスで満たしながら、コストを最小化できます。

🏗️ ソリューション アーキテクチャ

APIM Internal モードが正解の理由

🔒 要件① — 単一 Private IP + mTLS

APIM を Internal VNet 統合モードでデプロイすると、パブリックエンドポイントを持たない単一のプライベート IP アドレスのみが外部に公開されます。

APIM のポリシーエンジンで validate-client-certificate ポリシーを使用することで、相互 TLS (mTLS) — クライアント証明書の検証 — を実装できます。

⚡ 要件② — レート制限

APIM は rate-limit および rate-limit-by-key ポリシーを組み込みで提供します。

コードを書かずに GUI または XML ポリシーで、呼び出し元 IP・サブスクリプションキー・カスタム変数ごとのレート制限を設定できます。追加サービス不要です。

💰 要件③ — コスト最小化

同等機能を実現するために Application Gateway + Istio Service Mesh などを組み合わせると、複数サービスのコストが累積します。

APIM 単体ですべての要件を満たすため、追加サービスが不要でコストを最小化できます。Developer ティア（開発用）または Standard v2 ティアが最もコスト効果的です。

🌐 VNet 内での動作

VM と AKS が同一 VNet 内にあるため、APIM の Internal モードはパブリックインターネットを経由せず、VNet 内部の Private IP で通信します。

VM → APIM → AKS Ingress の経路がすべてプライベートネットワーク内で完結します。

⚙️ APIM の主要ポリシー機能

  • 1
    validate-client-certificate ポリシー：クライアント証明書を検証し mTLS を実装。証明書の発行者・サブジェクト・拇印による細かい制御が可能。
  • 2
    rate-limit ポリシー：時間窓あたりの呼び出し回数を制限（例：60秒あたり100回）。超過時は 429 Too Many Requests を返す。
  • 3
    rate-limit-by-key ポリシー：IP アドレス・ユーザーID・カスタムキーごとに個別レート制限を適用。
  • 4
    Internal VNet モード：パブリック IP を持たず、単一 Private IP のみ公開。インターネットからのアクセスを完全にブロック。
  • 5
    バックエンドルーティング：受信リクエストを AKS クラスターの内部サービスエンドポイントへルーティング。ロードバランシング・フォールバックも設定可能。

❌ 不正解となる選択肢とその理由

🔴

Application Gateway のみ

Application Gateway はレイヤー7のロードバランサーで、mTLS（クライアント証明書認証）には対応していますが、ネイティブのレート制限機能を持っていません。WAF ルールで一部制御可能ですが、精密なレート制限には向かず、また APIM よりコストが高くなります。

🔴

Azure Load Balancer (Internal) のみ

内部ロードバランサーは単一プライベート IP とレイヤー4の負荷分散を提供しますが、mTLS 認証もレート制限も提供しません。コストは最安ですが、要件を満たせません。

🔴

Azure Front Door

Azure Front Door はグローバルな HTTP/HTTPS ロードバランサーで、パブリック インターネット向けのサービスです。内部 VNet のみでのアクセス制限（単一プライベート IP）という要件を満たせません。

⚠️

Application Gateway + APIM の組み合わせ

機能的には要件をすべて満たしますが、2つのサービスのコストが累積します。「コストを最小化する」という要件に反するため、APIM 単体の Internal モードが優れた選択です。

⚠️

Istio Service Mesh のみ

Istio は AKS のアドオンとして Pod 間の mTLS を実現できますが、VM からの単一プライベート IP アクセスという要件には追加のイングレス設定が必要です。また、設定の複雑さとオーバーヘッドがあり、APIM 単体より管理コストが高くなります。

🎯 試験攻略ポイント まとめ

単一 Private IP = APIM Internal モード 「単一の Private IP」「プライベートのみ公開」が出たら APIM の Internal VNet 統合を即座に想起する
mTLS = APIM validate-client-certificate ポリシー APIM は組み込みで mTLS（クライアント証明書検証）に対応。追加サービス不要
レート制限 = APIM rate-limit ポリシー Application Gateway・Load Balancer にはネイティブレート制限がない。APIM の強みの一つ
コスト最小 = 1サービスで複数要件を満たす 複数サービスの組み合わせは要件を満たしても「コスト最小」に反する場合がある
APIM の VNet 対応ティア Consumption ティアは VNet 統合非対応。Developer / Basic v2 以上が必要
同一 VNet 内の通信 VM と AKS が同一 VNet なら、APIM Internal モードで完全にプライベートな通信経路を構築できる
