Azure Logic Apps × オンプレミス DB2
必要な Azure リソースとは

ハイブリッド環境でオンプレミスの DB2 データベースに Logic Apps からアクセスするための構成を徹底解説します。

📌 問題の本質
  • Logic Apps は Azure 上のクラウドサービス。オンプレミスのリソースへは直接アクセスできない
  • オンプレミスの DB2 はプライベートネットワーク内にあり、インターネット経由でのアクセスはセキュリティ上不可
  • Azure と オンプレミスの間に「安全な橋渡し役」が必要 → これが今回の答え

② 答え：作成すべき Azure リソース

✅ 正解

オンプレミスデータゲートウェイ
（On-premises Data Gateway）

Azure リソースとして「オンプレミスデータゲートウェイ」を作成し、オンプレミスサーバーにゲートウェイソフトウェアをインストールすることで、Logic Apps からオンプレミスの DB2 に安全にアクセスできます。

③ オンプレミスデータゲートウェイの仕組み

オンプレミスデータゲートウェイは「Azure リソース」と「オンプレミスのソフトウェア」の2つがセットで機能します。

☁️ Azure 側（Azure リソース）

  • Azure Portal でリソースとして作成する
  • リソースの種類：オンプレミスデータゲートウェイ
  • Logic Apps のコネクタ設定でこのリソースを指定する
  • リソース自体は「窓口の定義」のみ。実際の処理はソフトウェア側が行う

🏢 オンプレミス側（ソフトウェア）

  • Microsoft のサイトからゲートウェイソフトウェアをダウンロード・インストール
  • DB2 サーバーにアクセスできるオンプレミスのマシンに配置
  • インストール後に Azure の Entra ID アカウントでサインインして Azure リソースと紐付ける
  • 常時起動しておく必要がある（サービスとして動作）

🔢 データアクセスのリクエストフロー

1
Logic Apps のワークフローが DB2 コネクタを使ってデータ取得リクエストを発行
2
Logic Apps が指定されたオンプレミスデータゲートウェイ（Azure リソース）を経由して Azure Service Bus にリクエストをキューイング
3
オンプレミスのゲートウェイソフトウェアが Service Bus をポーリングしてリクエストを検出（アウトバウンド通信のみ）
4
ゲートウェイソフトウェアがオンプレミスの DB2 データベースにクエリを実行してデータを取得
5
取得したデータを Service Bus 経由で Logic Apps に返す → ワークフローが結果を受け取る ✅

🔌 Logic Apps の IBM DB2 コネクタ

Logic Apps には IBM DB2 専用のコネクタが用意されています。オンプレミスデータゲートウェイと組み合わせることでオンプレミスの DB2 に接続できます。

設定項目値
コネクタ名IBM DB2
接続方法オンプレミスデータゲートウェイ経由

対応操作テーブル取得・行の取得・行の挿入・行の更新・行の削除・ストアドプロシージャ実行

④ 間違いやすい選択肢と理由

❌ VPN ゲートウェイ（Virtual Network Gateway）
  • VNET とオンプレミスをネットワークレベルで接続するリソース
  • Logic Apps（従量課金・マルチテナント）は VNET に統合されないため VPN ゲートウェイだけでは DB2 に届かない
  • ISE（統合サービス環境）や Standard Logic Apps と VNET 統合を組み合わせれば可能だが、今回のシナリオで最もシンプルな答えではない
❌ Azure API Management（APIM）
  • API の公開・管理・保護のためのサービス
  • オンプレミスの DB2 への接続機能は持っていない
  • DB2 の前に API を置く構成も一般的ではなく、今回の要件には合わない
❌ Azure Data Factory
  • データ統合・ETL サービス。DB2 コネクタも存在する
  • ただしリアルタイムのワークフロー統合（Logic Apps の用途）には不向き
  • Data Factory もオンプレミス接続には「セルフホスト統合ランタイム」が必要で、オンプレミスデータゲートウェイとは別のもの
❌ Azure Relay
  • オンプレミスデータゲートウェイが内部的に使う Azure Service Bus の機能の一部
  • 直接 Azure リソースとして作成・設定するものではなく、ゲートウェイの内部実装として使われる
  • Relay を直接使う構成は複雑でオーバースペック

⑤ 類似サービスとの使い分け・試験頻出ポイント

📊 オンプレミス接続方式の比較

方式主な用途Logic Apps との相性特徴
オンプレミスデータゲートウェイ Logic Apps・Power BI・Power Automate からオンプレミス DB へのアクセス ✅ 最適 ソフトウェアをインストールするだけ。ファイアウォール開放不要
VPN Gateway（サイト間VPN） VNET とオンプレミスのネットワーク全体の接続 △ 追加設定が必要 Standard Logic Apps + VNET 統合が別途必要。大規模構成向け
ExpressRoute 高帯域・低遅延の専用線接続 △ 追加設定が必要 VPN より高信頼性・高コスト。エンタープライズ向け
セルフホスト統合ランタイム Azure Data Factory からオンプレミス DB へのアクセス ❌ Logic Apps では使わない Data Factory 専用のオンプレミス接続コンポーネント

🎯 試験で問われやすいポイント

⚠️ 引っかかりやすいポイント
  • 「Azure リソースを作成する」= オンプレミスデータゲートウェイ：ただしソフトウェアのインストール（オンプレミス側）とセットで初めて機能する
  • VPN Gateway と混同しない：VPN は「ネットワーク接続」。ゲートウェイは「アプリケーション接続」。用途が異なる
  • Logic Apps の種類に注意：消費（従量課金）プランの Logic Apps はゲートウェイ方式が標準。Standard プランは VNET 統合も選択肢になる
  • 対応サービス：オンプレミスデータゲートウェイは Logic Apps だけでなく Power BI・Power Automate・Analysis Services でも共用できる
  • 「ハイブリッド Entra テナント」という条件は認証方式（Entra ID でゲートウェイを認証登録する）に関係するが、リソースの選択自体には直接影響しない
📌 最終まとめ
  • Logic Apps からオンプレミス DB2 にアクセスするには オンプレミスデータゲートウェイ（Azure リソース）を作成する
  • あわせてオンプレミスサーバーにゲートウェイソフトウェアをインストールする（試験では「Azure リソース」を問う問題が多い）
  • Logic Apps 側では IBM DB2 コネクタを使い、ゲートウェイリソースを指定して接続する
  • 通信はオンプレミス側からのアウトバウンドのみ（ポート 443）で完結するためセキュア
  • 「セルフホスト統合ランタイム」は Data Factory 専用であり Logic Apps では使わない
