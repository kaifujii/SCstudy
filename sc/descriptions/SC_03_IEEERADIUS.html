01

まずたとえ話で整理する — 3つの規格は何者か

IEEE 802.1X・EAP・RADIUS という3つの名前はセットで語られることが多いため「ひとつの仕組み」に見えてしまいます。しかし実際にはそれぞれ別の組織が別の目的で作った独立した規格です。まずマンションのたとえで役割を分けてから、技術の話に進みましょう。

IEEE 規格 / L2
IEEE 802.1X
= オートロックのドアシステム
「確認が取れるまで絶対に開けない」という制御の仕組みそのものです。ドアは自分で「誰が入れるか」を判断せず、管理会社（RADIUS）の返事を待って開閉するだけ。IEEE 802.1 グループが策定したL2の規格です。
IETF 規格 / RFC 3748
EAP
= インターホンの会話ルール
「まずお名前を」「次に暗証番号を」というやりとりの形式を定めたルールブックです。EAP-TLS なら「証明書を提示して」、PEAP なら「パスワードを言って」と、中の方式を差し替えられます。IETF が RFC 3748 として策定。
IETF 規格 / RFC 2865
RADIUS
= 住民台帳を持つ管理会社
住民の名前・暗証番号・入れる部屋の情報を一元管理。ドアからの問い合わせに対して「OK」か「NG」かを判定して返す機関です。802.1X とは独立した IETF 規格（RFC 2865）で、VPN 等でも単独で使われます。

入館の流れをストーリーで読む

1
あなた（端末）がドア（ポート）に近づく。ドアは施錠されたまま（Controlled Port = ブロック状態）。守衛（スイッチ）が気づいて声をかける。
2
インターホン越しに「お名前を教えてください」というEAP の会話が始まる。守衛はあなたの答えをそのまま管理会社（RADIUS）に転送する。
3
管理会社が住民台帳と照合して「OK（Access-Accept）」を守衛に返す。このとき「101号室（VLAN 100）に通してよい」という動的 VLAN 情報も一緒に返すことができる。
4
守衛（スイッチ）がドアを開錠する（Controlled Port = 開放）。EAP-Success が端末に届き、通常のネットワーク通信が可能になる。
×
管理会社が「NG（Access-Reject）」を返した場合、ドアはブロックのまま。EAP-Failure が端末に届く。ゲスト VLAN への誘導もこのタイミングで行える。

3つの関係を一行で

IEEE 802.1X（IEEE規格）はドアを制御する「枠組み」、EAP（IETF規格）は認証情報を運ぶ「会話形式」、RADIUS（IETF規格）は本人かを判定する「サーバ」。3つは独立した別々の規格であり、802.1X が EAP・RADIUS を組み合わせて使うアーキテクチャを定義している。

EAP の「二重包み」とは：EAP メッセージは端末〜スイッチ間では EAPoL（Ethertype 0x888E）という封筒に入り、スイッチ〜RADIUSサーバ間では RADIUS パケット（属性 Type 79）という別の封筒に入れ替えられます。中の EAP メッセージは同じです。インターホンの会話内容を、守衛が別の電話で管理会社に伝えるイメージです。

03

IEEE 802.3（有線 LAN）規格群

IEEE 802.3 は有線 LAN（Ethernet）の物理層および MAC 副層を規定します。1983年初版策定。現在も高速化・PoE などの拡張が続いています。IEEE 802.1X は 802.3 ネットワーク上でも動作し、スイッチポートに適用することで有線接続端末にも認証を要求できます。

04

IEEE 802.11（無線 LAN）規格群

IEEE 802.11 は 1997年初版の無線 LAN 規格群です。セキュリティ拡張として IEEE 802.11i（WPA2 の基盤）が2004年に策定され、WPA2/WPA3-Enterprise モードで IEEE 802.1X が採用されています。

Wi-Fi 世代と 802.1X の関係

セキュリティ規格認証方式暗号化802.1X用途
WEP共有鍵RC4なし廃止・使用禁止
WPA2-PersonalPSK（事前共有鍵）CCMP（AES-128）なし家庭・小規模
WPA2-EnterpriseIEEE 802.1X + EAPCCMP（AES-128）必須企業・大規模
WPA3-PersonalSAE（Dragonfly）CCMP（AES-128）なし家庭（辞書攻撃耐性向上）
WPA3-EnterpriseIEEE 802.1X + EAPCCMP / GCMP-256必須企業（192-bit対応）

Personal vs Enterprise の決定的な違い：WPA2-Personal は全員が同じ PSK（パスワード）を使うため、1人が漏らすと全員が危険になります。WPA2-Enterprise は 802.1X + EAP による個人認証なので、ユーザごとに個別クレデンシャルを持ちアクセス制御・ログ管理も可能です。企業ネットワークには Enterprise が必須です。

IEEE 802.1X（Port-based Network Access Control / PNAC）は IEEE 802.1 グループの一規格です。ネットワークポートへのアクセスを認証によって制御し、有線（802.3）・無線（802.11）いずれにも適用できる汎用的な認証フレームワークです。

EAP 方式の比較 — 「会話の方式」を選ぶ

EAP（Extensible Authentication Protocol）はたとえ話の「インターホンでの会話ルール」です。方式によって「証明書を見せる」「パスワードを言う」など中身が変わります。EAP 自体は封筒であり、中の方式（TLS/MSCHAPv2等）を差し替えられるのが特徴です。

インタラクティブ — EAP 方式フィルター

条件ボタンで絞り込みができます。試験で「クライアント証明書が必要な方式は？」を解くときに使ってください。

EAP 方式サーバ証明書クライアント証明書クライアント認証強度RFC
EAP-MD5不要不要チャレンジ/レスポンス低・非推奨RFC 3748
EAP-TLS必要必要クライアント証明書（相互認証）最高RFC 5216
EAP-TTLS必要不要ID/PW（TLSトンネル内）高RFC 5281
PEAP必要不要MSCHAPv2 等（TLS内）高IETF Draft
EAP-FAST任意（PAC）不要PAC + ID/PW中〜高RFC 4851
PEAP
PEAP の二層構造（たとえ：二重扉の通路）：Phase 1 でサーバ証明書だけを使って TLS トンネル（暗号化された通路）を確立し、Phase 2 でその通路の中で MSCHAPv2 などの ID/PW 認証を実行します。クライアント証明書は不要なため導入コストが低く Microsoft 環境で主流です。
TLS
EAP-TLS（たとえ：社員証を両者が提示して確認）：サーバ・クライアント双方の証明書による相互認証。パスワードレスで最も強固です。全端末への証明書発行・管理コストが高い。「クライアント証明書が必要 = EAP-TLS」は試験の鉄則。
!
EAP-MD5 は無線 LAN では絶対禁止（たとえ：電話番号だけで本人確認する欠陥システム）：サーバ認証がないため攻撃者が偽の認証サーバになりすませます（MITM 攻撃）。現在は有線でも非推奨です。

セキュリティ上の考慮事項

EAPoL-Logoff 偽装（DoS）

偽の EAPoL-Logoff フレームで認証済みポートを強制ブロックする DoS 攻撃。たとえ：インターホンに「もう帰ります」と偽の声を吹き込んでドアを閉めさせる行為。

対策：MAC アドレス検証・MACsec（802.1AE）でフレーム完全性を保護

中間者攻撃（Rogue RADIUS）

PEAP でサーバ証明書検証を無効にすると、攻撃者が偽の RADIUS サーバを立て ID/PW を窃取。たとえ：本物の管理会社を騙る偽の会社に守衛が電話をかけてしまう。

対策：PEAP は必ずサーバ証明書を検証。信頼する CA を明示的に指定する

ハブ接続による認証回避

認証済みポートの背後にハブを接続し未認証デバイスを通過させる。たとえ：認証済みの住民がエントランスドアを押さえて、認証を受けていない来訪者を一緒に入れてしまう。

対策：MACsec（802.1AE）の導入。ポートあたりの MAC アドレス数制限

VLAN ホッピング

動的 VLAN 割り当て環境での VLAN タギング不備を悪用し他の VLAN にアクセスする。たとえ：101号室に通された住民が、鍵のかかっていない管理者専用フロアに侵入する。

対策：DTP（Dynamic Trunking Protocol）の無効化。ネイティブ VLAN の変更

推奨セキュリティ対策

1. EAP 方式は EAP-TLS（最推奨）または PEAP/EAP-TTLS（サーバ証明書の検証を必須設定）を選択
2. RADIUS 通信に RadSec（RADIUS over TLS / RFC 6614） を適用して通信路全体を保護する
3. MACsec（IEEE 802.1AE） を有線 LAN に適用して L2 フレームを暗号化・完全性保護する
4. RADIUS サーバを冗長化してシングルポイント障害を排除する
5. ゲスト VLAN・認証失敗 VLAN を設定して未認証端末を隔離する

過去問スタイル 練習問題

情報処理安全確保支援士試験の出題傾向（R6秋・R4春・H30秋・H29春など）に沿った練習問題です。選択肢をクリックすると正誤と解説が表示されます。

Q1IEEE 802.1X に関する記述として、最も適切なものはどれか。
正解：ウ
IEEE 802.1X は IEEE 802.1 グループ（管理・セキュリティ担当）の規格です。有線 LAN（802.3）・無線 LAN（802.11）の両方に適用でき、ポートベースのアクセス制御を規定します。
ア：誤り。有線スイッチポートにも適用できます。
イ：誤り。RFC 2865・UDP 1812/1813 は RADIUS の説明です（IETF 規格）。802.1X は IEEE 規格です。
エ：誤り。認証の判定は認証サーバ（RADIUS サーバ）が行います。たとえ話：「管理会社が入館可否を決める。守衛は連絡係」。
Q2IEEE 802.1X 認証における RADIUS サーバの役割として最も適切なものはどれか。
正解：イ
RADIUS（RFC 2865）は IETF が規定した独立した規格です。802.1X の一部ではありません。VPN・ダイヤルアップ等でも単独で使われます。
ア：誤り。RADIUS はオーセンティケータと UDP で通信します（サプリカントと直接はやり取りしません）。
ウ：誤り。RADIUS は 802.1X の一部ではなく独立した規格です。
エ：誤り。EAPoL ⇔ RADIUS 変換を行うのはオーセンティケータ（守衛）です。
Q3IEEE 802.1X で利用される EAP 方式の説明として正しいものはどれか。
正解：イ
PEAP：Phase 1（TLS トンネル確立：サーバ証明書のみ）→ Phase 2（MSCHAPv2 等のパスワード認証）。
ア：誤り。EAP-TLS はサーバ・クライアント双方の証明書が必要です（相互認証）。
ウ：誤り。EAP-MD5 はサーバ認証がなく中間者攻撃に脆弱。無線 LAN では使用禁止。
エ：誤り。EAP-TLS は全端末へのクライアント証明書配布・管理コストが高い。
Q4IEEE 802.1X 認証後、ユーザを所属部門の VLAN に自動割り当てするために RADIUS の Access-Accept に付加する属性の組み合わせとして正しいものはどれか。
正解：ウ
動的 VLAN 割り当ては属性64・65・81の3点セットです。
・Tunnel-Type（64）：値13 = VLAN
・Tunnel-Medium-Type（65）：値6 = IEEE 802
・Tunnel-Private-Group-ID（81）：VLAN ID（例："100"）
ア は Access-Request（要求側）で使われる属性。イ は EAP 搬送・整合性確認用。エ は接続元情報記録用。
Q5有線 LAN に IEEE 802.1X 認証を導入した環境で、認証済みクライアント PC の背後にリピータハブを接続した場合に生じるリスクとして最も適切なものはどれか。
正解：イ
802.1X の認証はポート単位で行われます。1 ポートが認証済みになるとそのポートに接続されたハブ配下のすべてのデバイスがネットワークにアクセス可能になります（802.1X の根本的な限界）。
たとえ話：「認証済みの住民がドアを押さえて、認証を受けていない来訪者を一緒に入れてしまう」状況です。
対策：MACsec（802.1AE）でフレームレベルの認証・暗号化を行う。
Q6WPA2-Enterprise 環境で EAP-TLS 認証を使用している場合、PEAP（MSCHAPv2）に変更することのデメリットとして最も適切なものはどれか。
正解：ウ
EAP-TLS → PEAP への変更の本質的なデメリットは「証明書認証からパスワード認証への後退」です。
・EAP-TLS：証明書でのみ端末を認証 → パスワードが存在しない → 辞書攻撃・フィッシング耐性が高い
・PEAP：パスワード認証 → 漏洩リスク。さらにサーバ証明書検証を無効化すると偽 RADIUS サーバへ接続する MITM 攻撃が成立しクレデンシャルを窃取される危険がある
ア・イ：逆。PEAP はサーバ証明書は必要だがクライアント証明書は不要。
エ：誤り。PEAP は TLS トンネル内で認証を行うため内部通信は暗号化されています。

重要用語まとめ

試験頻出キーワード

IEEE 802.1XIEEE 802.1 グループのポートベース NAC 規格。有線・無線双方に適用可能。「オートロックドアシステム」のたとえ。
EAPoLEAP over LAN。Ethertype 0x888E。サプリカント〜オーセンティケータ間で EAP メッセージを運ぶ L2 搬送プロトコル。「インターホン線」のたとえ。
Supplicant認証を要求するエンティティ（端末）。「マンションに入ろうとする来訪者」のたとえ。
AuthenticatorEAP メッセージを中継するスイッチや AP。RADIUS クライアントとして動作し、判断は認証サーバに委ねる。「守衛室の守衛」のたとえ。
RADIUSRFC 2865（IETF）。AAA（認証・認可・アカウンティング）サービスを提供。UDP 1812/1813。「住民台帳を持つ管理会社」のたとえ。
EAP-TLSクライアント・サーバ双方の証明書による相互認証。最もセキュア（RFC 5216）。クライアント証明書が必要な点が試験頻出。
PEAP外側 TLS トンネル（サーバ証明書のみ）＋内側 MSCHAPv2 等の二層構造。クライアント証明書不要。Microsoft 環境で主流。
動的 VLANRADIUS Access-Accept の Tunnel 属性（64/65/81）でユーザごとに VLAN を自動割り当て。「どの部屋に通すか」のたとえ。
Controlled Port認証前はブロック、認証後に開放されるデータ通信用の論理ポート。「エントランスのドア」のたとえ。
Uncontrolled PortEAPoL フレームのみ常時通過を許可する認証専用の論理ポート。「インターホン回線」のたとえ。
MACsecIEEE 802.1AE。L2 フレームの暗号化・完全性保護（GCM-AES）。802.1X の MKA と連携して鍵交換。
WPA2-EnterpriseIEEE 802.11i のエンタープライズモード。IEEE 802.1X + EAP + CCMP（AES-128）。RADIUS サーバ必須。
RadSecRADIUS over TLS（RFC 6614）。RADIUS の通信路全体を TLS で保護する拡張規格。
CoAChange of Authorization（RFC 5176）。認証後にポリシーを動的変更・強制切断する機能。
MABMAC Address Bypass。802.1X 非対応機器に対して MAC アドレスで認証を代替。MAC アドレス詐称に脆弱。

試験対策 5つの鉄則

1. IEEE 802.1X（IEEE規格）と RADIUS（IETF/RFC 2865）は別々の規格 — ドアシステムと管理会社は別組織
2. オーセンティケータは認証の判断をしない — EAPoL ⇔ RADIUS 変換をするだけ。判断は RADIUS サーバ
3. EAP-TLS = クライアント証明書も必要、PEAP = サーバ証明書のみ必要 — この差が最頻出
4. 動的 VLAN は属性64・65・81 の3点セット — 試験で単独問題として出題される
5. 802.1X は有線・無線どちらにも適用できる — WPA2/WPA3-Enterprise の認証基盤として利用
