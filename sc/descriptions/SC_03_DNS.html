DNS全体のたとえ話

DNSは「インターネットの電話帳」です。ドメイン名（例: www.bank.jp）を「銀行本店の住所（IPアドレス）」に変換します。セキュリティ問題も電話帳に置き換えると直感的に理解できます：キャッシュポイズニングは「電話帳の番号をこっそり詐欺師の番号に書き換える」、アンプ攻撃は「大量の返信はがきを他人の住所で郵便局に一気に送りつけて業務麻痺させる」攻撃です。

各攻撃の詳細なたとえ話 → S04〜S09
Web閲覧時
URLを打つたびに裏でDNSが動く。ブラウザ → スタブリゾルバ → フルサービスリゾルバ の流れ。
設計上の弱点
1980年代設計。認証なし・UDP平文が前提。後付けのDNSSEC / DoT / DoH で補強している。
試験で問われる核心
「どの攻撃にどの対策が有効か」「DNSSECとDoTの違い」「BCP38が効かない攻撃はどれか」の3点が最頻出。
シラバス対応
3-5（ネットワーク機器セキュリティ）・3-1（暗号利用・鍵管理）・3-4（セキュリティ監視）と密接に連携。

ROOT → TLD → 権威NSの信頼の連鎖を繋ぐ重要なレコード

否定応答の証明
「このドメインは存在しない」ことを暗号的に証明。NSEC3はゾーン列挙攻撃対策でハッシュ化。
NSECはゾーン列挙攻撃（全ドメインを推定）に弱い→NSEC3でハッシュ化して対策

04

DNS キャッシュポイズニング

フルサービスリゾルバのキャッシュに偽のDNS応答を注入し、正規ドメインへのアクセスを偽サイトへ誘導する攻撃です。TTL期間中は多数の利用者が被害を受け続けます。

たとえ話：電話帳への不正書き込み

図書館の共有電話帳（リゾルバキャッシュ）の「銀行A」の番号を、攻撃者がこっそり詐欺グループの番号に書き換えます。電話帳を参照した全利用者が詐欺グループに繋いでしまい、書き換えはTTLが切れるまで有効です。

技術的には → リゾルバキャッシュへの偽Aレコード注入（TXID推測 + src IP偽装）

DNSSEC（DNS Security Extensions）

DNSSECはDNSにデジタル署名を追加することで、応答データの完全性（改ざん検知）と真正性（正規ゾーン管理者からの応答）を保証する拡張仕様（RFC 4033〜4035）です。

DNSSECのたとえ話：公証役場のハンコが押された電話帳

DNSSECは「公証役場のハンコが押された電話帳」です。誰かが番号を書き換えようとしても、公証役場のハンコ（デジタル署名）が変わり改ざんを検出できます。ただし電話帳の内容は暗号化されていない（中身は誰でも見える）点がDoT/DoHとの大きな違いです。

重要区別：DNSSECは「署名検証（改ざん検知）」、DoT・DoHは「通信の秘匿（暗号化）」

DNSSECとDoT/DoHの役割分担（最頻出）

DNSSECは「応答が本物かどうかの署名検証」であり通信の暗号化ではない。クエリ内容の秘匿はDoT/DoHが担う。たとえると：DNSSECは「正しい目的地へ案内する地図の真偽検証」、DoT/DoHは「地図を見る会話を盗み聞きされないようにする」役割分担。2つは別の問題を解決する相補的な技術です。

DNSSEC はアンプ攻撃の対策にならない（重要）：DNSSECを有効にするとRRSIG・DNSKEY・NSECなどのレコードが応答に追加されるため、応答サイズが増大します。ANYクエリへの応答が数KB単位になる場合があり、DNSアンプ攻撃の増幅効果（BAF）を逆に高めてしまう可能性があります。DNSSEC有効ゾーンのオープンリゾルバは特に踏み台として危険です。

07

DNS リフレクション攻撃

攻撃者が送信元IPを標的のIPに偽装してDNSサーバに問い合わせを送ることで、DNSサーバの応答を標的に集中させる攻撃です。オープンリゾルバを踏み台にして行われます。

たとえ話：差出人住所を偽装した大量返信はがき

差出人住所を「被害者の住所」に偽って、各家庭（オープンリゾルバ）にアンケートはがきを大量送付します。各家庭が返信を出すと全部「被害者」のポストに届き、ポストが溢れて正常な郵便が受け取れなくなります。

技術的には → src IP偽装UDPクエリ → オープンリゾルバが標的IPへ応答を返送 → 帯域飽和
問題
オープンリゾルバ（Open Resolver）：外部の任意ホストからの再帰問い合わせに応じるDNSサーバ。本来は自組織クライアントのみに応じるべき。BINDなら allow-recursion { 自組織; }; で制限。インターネット上に無数に存在し踏み台として悪用される。
対策1
BCP38 / uRPF：ISPがネットワーク境界でIPソースアドレスを検証し偽装パケットの送出を防ぐ。リフレクション・アンプ攻撃の根本抑止。
対策2
オープンリゾルバの廃止：外部からの再帰問い合わせをACLで拒否。踏み台になることを防ぐ直接対策。
対策3
RRL（Response Rate Limiting）：同一宛先への応答を一定レートに制限。踏み台になった際のトラフィック増幅を抑制。BIND 9.9以降で標準サポート。
08

DNS アンプ攻撃（増幅型 DDoS）

リフレクション攻撃の進化形で、小さな問い合わせに対して非常に大きな応答を返すDNSの特性（特にANYクエリ）を悪用して帯域を増幅させます。BAF（Bandwidth Amplification Factor）が高いほど効率的な攻撃が可能です。

たとえ話：1枚のはがきが100ページの返信を引き出す

1枚のはがき（〜40バイトのANYクエリ）を送ると、DNSサーバが100ページ分の返信（〜4,000バイトの応答）を引き出してくれます。差出人住所を被害者に偽装すれば、この大量の返信が全部被害者のポストに届きます。少ない帯域で100倍超の攻撃が可能なのが最大の特徴です。

重要：DNSSECを有効にするとRRSIG等が加わり応答がさらに増大→BAFが上昇してアンプ攻撃に逆効果

水攻め攻撃（ランダムサブドメイン攻撃）

ランダムに生成したサブドメイン（例: a1b2c3.example.jp）を大量に問い合わせ、対象ドメインの権威DNSサーバをリソース枯渇させる攻撃です。IPスプーフィング不要がBCP38対策を無効にする最大の特徴です。

たとえ話：存在しない本を大量リクエストして図書館を麻痺させる

図書館（権威DNS）に「ランダムなタイトルの本を貸してください」という問い合わせを無数に送ります。司書はその都度棚を全部探さなければならず（NXDOMAIN）、在庫なしはメモできますが（ネガティブキャッシュ）、次は別のランダムタイトルなので毎回探し直しです。司書（CPU/メモリ）が疲弊して通常業務が止まります。

最大の特徴：普通のIPアドレスから送るだけで成立 → BCP38が無効な唯一のDNS攻撃

リフレクション攻撃にANYクエリの大応答を組み合わせ。BAF最大100倍超の増幅で少ない帯域から大規模DDoSが可能。DNSSEC有効ゾーンはRRSIGで応答がさらに増大。

過去問スタイル 練習問題

情報処理安全確保支援士試験の出題傾向に沿った練習問題です。選択肢をクリックすると正誤と解説が表示されます。

Q1DNSキャッシュポイズニング攻撃の説明として最も適切なものはどれか。
正解：ウ
DNSキャッシュポイズニングはフルサービスリゾルバのキャッシュに偽応答を書き込み、利用者を偽サイトへ誘導する攻撃です。
ア：DNS水攻め攻撃の説明。イ：DNSリフレクション攻撃の説明。エ：存在しない攻撃の説明（DNSSECを「無効化」はできない）。
Q2カミンスキー攻撃への緊急対策として2008年に広く実装されたものはどれか。
正解：イ
カミンスキー攻撃（2008年）への緊急対策が「ソースポートランダム化」です。TXID（16bit）× 送信元ポート（16bit）≒ 2の32乗通りに推測空間を拡大し実用的な攻撃を困難にしました。
ウ：DNSSECが根本的解決策ですが、緊急対策はソースポートランダム化でした（DNSSECの導入は時間がかかる）。
Q3DNSSECに関する記述として適切なものはどれか。
正解：イ
DNSSECの鍵構造の核心：ZSK→各RRsetに署名（RRSIG）、KSK→ZSKのDNSKEYに署名、KSKのハッシュを親ゾーンにDS登録で信頼チェーン確立。
ア：誤り。DNSSECは暗号化でなく「署名検証」。通信の暗号化はDoT/DoH。
ウ：誤り。DNSSECはアンプ攻撃対策にならず逆にRRSIGで応答増大の可能性。
エ：誤り。DSレコードは「子ゾーンのKSKハッシュを親ゾーンに登録するレコード」。
Q4DNSアンプ攻撃を防止するために有効な対策の組合せとして最も適切なものはどれか。
正解：イ
DNSアンプ攻撃はIPスプーフィングを前提とするため、BCP38でスプーフィングを防ぐことが根本対策。オープンリゾルバ廃止で踏み台になることを防ぎます。
ア：DNSSECはアンプ攻撃対策にならない（逆に増幅増加）。DoTはキャッシュポイズニング対策。
エ：ソースポートランダム化はキャッシュポイズニング対策。
Q5DNS水攻め攻撃（ランダムサブドメイン攻撃）の特徴として最も適切なものはどれか。
正解：ウ
水攻め攻撃の本質は「ランダムなサブドメインはキャッシュに入らない」こと。全クエリが権威NSへ転送されるため二重の過負荷が発生します。
ア：水攻めはIPスプーフィング不要→BCP38は有効でない。これが最重要の区別ポイント。
イ：キャッシュポイズニングの説明。エ：DNSアンプ攻撃の説明。
Q6DNS over TLS（DoT）を利用する主な目的として最も適切なものはどれか。
正解：ウ
DoT（RFC 7858）はTCPポート853を使用しDNSをTLS暗号化。通信路での盗聴・改ざん防止が主目的。
ア：これはDNSSECの説明。DoTは暗号化（秘匿）、DNSSECは署名（正当性検証）の役割を混同しないこと。

重要用語まとめ

フルサービスリゾルバ再帰問い合わせを行いキャッシュするDNSサーバ。ISP・企業内に設置。キャッシュポイズニングや水攻めの標的。
権威DNSサーバ特定ゾーンのDNSデータを管理・提供するサーバ。水攻め攻撃の直接の標的。
TTL（Time To Live）DNSキャッシュの有効期間（秒）。汚染時の被害継続時間に直結する。長すぎず短すぎない設定が重要。
トランザクションID（TXID）DNSクエリ・応答を照合する16bitの識別子（65,536通り）。カミンスキー攻撃の推測対象。
ソースポートランダム化カミンスキー攻撃対策。送信元UDPポートをランダム化し推測空間を約2の32乗に拡大する。2008年の緊急対策。
0x20エンコードクエリのドメイン名大小文字をランダム化（wWw.BaNk.Jp）し応答の正当性を検証する技法。
DNSSECDNS Security Extensions。デジタル署名でDNS応答の完全性・真正性を保証。暗号化ではない。RFC 4033〜4035。
KSK（鍵署名鍵）ZSKのDNSKEYに署名する鍵。長期間・高セキュリティで管理（年1回程度更新）。親ゾーンにDSレコードを登録。
ZSK（ゾーン署名鍵）ゾーン内の各RRsetに署名する鍵（月1回程度更新）。KSKよりも頻繁にローテーション。
RRSIGリソースレコードセットに付与されたDNSSECの電子署名レコード。ZSKで生成。
DNSKEYDNSSECの公開鍵（KSK・ZSK）を格納するリソースレコード。
DS（Delegation Signer）子ゾーンのKSKハッシュを親ゾーンに登録するレコード。信頼チェーンの「継ぎ手」。
NSEC / NSEC3DNSSECの否定応答レコード。NSEC3はゾーン列挙攻撃対策でハッシュ化。
DoT（DNS over TLS）TCP 853でDNSをTLS暗号化。盗聴・通信路改ざん防止。DNSSECと相補的。RFC 7858。
DoH（DNS over HTTPS）TCP 443でDNSをHTTPS暗号化。プライバシー保護とファイアウォール透過の両面。RFC 8484。
オープンリゾルバ外部からの再帰問い合わせに応じるDNSサーバ。リフレクション・アンプ攻撃の踏み台。廃止が基本対策。
BCP38（RFC 2827）ネットワークエッジでのソースIPフィルタリング標準。IPスプーフィングを防ぎリフレクション・アンプ攻撃の根本対策。水攻めには無効。
RRL（レスポンスレートリミット）DNSサーバが同一宛先への応答レートを制限する機能。アンプ・水攻め対策。BIND 9.9以降で標準サポート。
BAF（増幅係数）Bandwidth Amplification Factor。クエリサイズに対する応答サイズの比率。DNSアンプ攻撃の効率指標。最大100倍超。
RPZ（Response Policy Zone）DNS Firewallの実装技術。ドメインベースのポリシーで悪意ある問い合わせを遮断。水攻め・マルウェアC&C対策。
uRPF（Unicast RPF）ルータでの逆経路確認によるソースIP検証。BCP38の実装手段の一つ。
RTBHRemotely Triggered Black Hole。大規模DDoS時にBGPで特定IPのルートを廃棄してトラフィックを遮断。
RFC 84822019年標準化。ANYクエリへの最小応答を規定。DNSアンプ攻撃の増幅率低減に有効。

試験対策 6つの鉄則

1. キャッシュポイズニング ≠ DDoS — 前者は「誘導」、後者は「停止」が目的
2. DNSSEC は暗号化ではない — 署名検証（正当性確認）。通信秘匿は DoT / DoH
3. 水攻めはIPスプーフィング不要 — BCP38が有効でない唯一のDNS攻撃
4. アンプ攻撃に DNSSEC は逆効果 — RRSIG等で応答サイズが増加しBAFが上昇
5. KSKはZSKに署名、ZSKはRRsetに署名 — 二層構造を混同しない
6. カミンスキー対策はソースポートランダム化（緊急）、根本対策はDNSSEC
