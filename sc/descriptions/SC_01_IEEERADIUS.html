01

まずたとえ話で整理する — IEEE 802.1X・EAP・RADIUS の関係

IEEE 802.1X・EAP・RADIUS は3つとも「ネットワークに接続しようとする人を認証する」ための仕組みです。しかしそれぞれ担う役割はまったく異なります。技術の話に入る前に、身近なたとえで役割を整理します。

たとえ話 ─ マンションのオートロック入館管理

あなたが初めて訪れるマンションに入ろうとする場面を想像してください。エントランスにはオートロックのドアがあり、インターホンで管理会社に確認してもらわないと入れません。

IEEE 802.1X = オートロックのドアシステム

「確認が取れるまでドアを絶対に開けない」という制御の仕組みそのものです。

ドア自体は「誰が入れるか」を判断しません。管理会社（RADIUS）の返事を待って開閉するだけ。IEEE（米国電気電子学会）が策定した L2（データリンク層）の規格です。

EAP = インターホンの会話ルール

「まずお名前を」「次に暗証番号を」といったやりとりの形式を定めたルールブックです。

EAP-TLS なら「証明書を見せて」、PEAP なら「パスワードを言って」と方式を差し替えられます。IETF が RFC 3748 として策定しました。

RADIUS = 住民台帳を持つ管理会社

住民の名前・暗証番号・入れる部屋の情報を管理。ドアからの問い合わせに対して「OK」か「NG」かを判定して返す機関です。

IETF が RFC 2865 として別途策定した独立した規格。VPN・ダイヤルアップ等でも単独で使われます。

入館の流れをストーリーで読む

1
あなた（端末）がドア（802.1X のポート）に近づく。ドアは施錠されたまま（Controlled Port = ブロック状態）。
2
インターホン（EAPoL）越しに「名前を教えてください」という会話（EAP）が始まる。会話の形式は EAP が定める。
3
ドア（オーセンティケータ）は受け取った情報を管理会社（RADIUS）に転送する。ドア自体は判断しない。
4
管理会社が住民台帳を照合してAccess-Accept（OK）を返す。
5
ドア（802.1X）が開錠する（Controlled Port = 開放状態）。通常のネットワーク通信が可能になる。
✕
管理会社がAccess-Rejectを返した場合、ドアはブロックのまま。ゲスト VLAN への誘導もここで行える。

3つの関係を一行で

IEEE 802.1X（IEEE規格）はドアを制御する「枠組み」、EAP（IETF規格）は認証情報を運ぶ「会話形式」、RADIUS（IETF規格）は本人かを判定する「サーバ」。3つは別々の規格であり、802.1X が外側の枠として EAP・RADIUS を呼び出す関係にある。

EAP の二重包み：EAP メッセージは端末〜スイッチ間では EAPoL（Ethertype 0x888E）という封筒に入り、スイッチ〜RADIUSサーバ間では RADIUS パケット（属性 Type 79）という別の封筒に入れ替えられて運ばれます。中身（EAP）は同じです。

IEEE 802 は IEEE（米国電気電子学会）の標準化委員会が策定する LAN・MAN 規格群の総称です。1980年2月に発足し「802」の名称はその年月に由来します。OSI 参照モデルのデータリンク層（L2）と物理層（L1）を対象として規格化しています。

IEEE 802.11（無線 LAN）規格群

05

IEEE 802.1X の詳細

IEEE 802.1X（Port-based Network Access Control）は IEEE 802.1 グループの一規格であり、ネットワークポートへのアクセスを認証によって制御します。有線（802.3）・無線（802.11）いずれにも適用できる汎用的な認証フレームワークです。

3つの構成要素

Supplicant（サプリカント）
ネットワーク接続を要求するエンティティ（端末）。EAPoL で認証情報を送出。Windows・macOS・Linux に標準内蔵。
Authenticator（オーセンティケータ）
スイッチ・AP。EAPメッセージを中継するだけで認証判断は行わない。RADIUSクライアントとして動作する。
Authentication Server（認証サーバ）
認証の可否を判定するサーバ。通常はRADIUSサーバ。LDAP/ADと連携してクレデンシャルを検証する。

Controlled Port / Uncontrolled Port

ポート種別役割認証前認証後
Uncontrolled PortEAPoL のみ通過させる認証専用ポート常時開放常時開放
Controlled Port通常のデータトラフィックが通過するポート閉鎖（ブロック）開放（許可）

802.1X と RADIUS の関係 — 規格としての違い

ここが本資料の核心です。IEEE 802.1X と RADIUS は別々の規格であり、802.1X が RADIUS を「認証サーバの実装」として外部から呼び出す関係にあります。

図 2 — IEEE 802.1X と RADIUS の関係図

規格の違いを整理する

比較軸IEEE 802.1XRADIUS（RFC 2865）
策定機関IEEE（米国電気電子学会）IETF（インターネット技術タスクフォース）
OSI 層データリンク層（L2）アプリケーション層（L7）/ UDP
役割ポートアクセス制御フレームワーク。「誰を通すか」の制御機構AAA（認証・認可・アカウンティング）サービス。「本人かどうか」の判定エンジン
プロトコルEAPoL（Ethertype 0x888E）UDP（認証: 1812、アカウンティング: 1813）
依存関係認証サーバとして RADIUS を利用。RADIUS がなくてもフレームワークとして独立して存在する802.1X と独立して存在。VPN・ダイヤルアップ等でも使われる
EAP の扱いEAP メッセージを EAPoL に格納して L2 伝送EAP メッセージを RADIUS 属性（Type 79）に格納して L7 伝送

RADIUS の AAA 機能と動的 VLAN 割り当て

Authentication（認証）
本人確認。証明書・パスワードを検証し Access-Accept / Reject を返す。UDP 1812。
Authorization（認可）
アクセス権限付与。VLAN 割り当て・ACL などを Access-Accept の属性として付加する。
Accounting（アカウンティング）
接続開始・終了・使用量の記録。課金・監査ログ目的。UDP 1813。

動的 VLAN 割り当て（試験頻出）：RADIUS の Access-Accept に属性 64（Tunnel-Type = 13/VLAN）・65（Tunnel-Medium-Type = 6/IEEE 802）・81（Tunnel-Private-Group-ID = VLAN ID）を3点セットで付加することで、認証結果に応じてユーザを自動的に適切な VLAN に配置できます。

07

EAP 方式の比較

EAP（Extensible Authentication Protocol / RFC 3748）は IETF が規定した認証フレームワークです。802.1X は EAP を「認証情報の搬送プロトコル」として使用し、実際の認証方式は EAP のサブプロトコルが担います。

EAP 方式サーバ証明書クライアント証明書認証情報強度RFC
EAP-MD5不要不要チャレンジ/レスポンス低・非推奨RFC 3748
EAP-TLS必要必要証明書（相互認証）最高RFC 5216
EAP-TTLS必要不要ID/PW（TLS トンネル内）高RFC 5281
PEAP必要不要MSCHAPv2 等（TLS 内）高IETF Draft
EAP-FAST任意（PAC）不要PAC + ID/PW中〜高RFC 4851
PEAP
PEAP の構造：Phase 1 で TLS ハンドシェイク（サーバ証明書のみ）→ 暗号化トンネル確立 → Phase 2 でトンネル内に MSCHAPv2 等の ID/PW 認証を実行。クライアント証明書は不要なため導入コストが低い。Microsoft 環境で主流。
TLS
EAP-TLS の特徴：サーバ・クライアント双方の証明書による相互認証。パスワードレスで最も強固。全端末への証明書発行・管理コストが高い。「クライアント証明書が必要 = EAP-TLS」は試験の鉄則。
!
EAP-MD5 は無線 LAN で禁止：サーバ認証がないため偽の認証サーバになりすましが可能（MITM 攻撃）。有線 LAN でも非推奨。

認証シーケンス図（UML 準拠）

UML の正式記法（ライフライン＝縦破線、実行仕様＝アクティベーションボックス、同期メッセージ＝実線塗りつぶし三角、応答メッセージ＝破線開き三角）で 802.1X 認証フローを示します。

シーケンス図 — IEEE 802.1X 認証フロー（UML 準拠）

①
EAPoL-Start：サプリカントが自発的に認証開始を要求します。EAPoL（Ethertype 0x888E）の L2 フレームとして送出されます。
④⑧
EAPoL → RADIUS 変換：オーセンティケータが EAPoL フレームを受け取り、EAP メッセージを RADIUS パケットに詰め替えてサーバへ転送します。オーセンティケータ自身は認証の判断をしません。
⑨
Access-Accept：RADIUS サーバが認証成功を通知。動的 VLAN 割り当てを行う場合は Tunnel 属性（64・65・81）がここで付加されます。
✕
Access-Reject の場合：Controlled Port はブロックのまま維持。ゲスト VLAN や検疫 VLAN への誘導（VLAN ステアリング）はここで行えます。
09

セキュリティ考慮事項

EAPoL-Logoff 偽装（DoS）

偽の EAPoL-Logoff フレームで認証済みポートを強制ブロックする DoS 攻撃。送信元 MAC アドレスの検証が容易でないため有効。

対策：MAC アドレス検証・MACsec（802.1AE）でフレーム完全性保護

中間者攻撃（Rogue RADIUS）

EAP-MD5 や PEAP でサーバ証明書検証を無効にした場合、攻撃者が偽の RADIUS サーバを立て ID/PW を窃取できる。

対策：EAP-TLS / PEAP では必ずサーバ証明書を検証。信頼する CA を明示指定

ハブ接続による認証回避

認証済みポートの背後にハブを接続し、未認証デバイスを通過させる攻撃。802.1X のポート単位制御の限界を突く。

対策：MACsec（802.1AE）の導入。ポートあたりの MAC アドレス数制限

VLAN ホッピング

動的 VLAN 割り当て環境での VLAN タギング不備を悪用し、他の VLAN にアクセスする攻撃。

対策：DTP（Dynamic Trunking Protocol）の無効化。ネイティブ VLAN の変更

推奨セキュリティ対策

1. EAP 方式は EAP-TLS（最推奨）または PEAP/EAP-TTLS（サーバ証明書の検証を必須設定）を選択する
2. RADIUS 通信に RadSec（RADIUS over TLS / RFC 6614） を適用して通信路全体を保護する
3. MACsec（IEEE 802.1AE） を有線 LAN に適用して L2 フレームを暗号化・完全性保護する
4. RADIUS サーバを冗長化してシングルポイント障害を排除する
5. ゲスト VLAN・認証失敗 VLAN を設定して未認証端末を隔離する

過去問スタイル 練習問題

情報処理安全確保支援士試験の出題傾向（R6秋・R4春・H30秋・H29春など）に沿った練習問題です。選択肢をクリックすると正誤と解説が表示されます。

Q1IEEE 802.1X に関する記述として、最も適切なものはどれか。
正解：ウ
IEEE 802.1X は IEEE 802.1 グループ（管理・セキュリティ担当）の規格です。有線 LAN（802.3）・無線 LAN（802.11）の両方に適用でき、ポートベースのアクセス制御を規定します。
ア：誤り。有線 LAN スイッチポートにも適用できます。
イ：誤り。RFC 2865・UDP 1812/1813 は RADIUS の説明です。802.1X とは別の規格（IEEE 規格）です。
エ：誤り。認証の判定は認証サーバ（RADIUS サーバ）が行います。オーセンティケータは EAP メッセージを中継するだけです。
Q2IEEE 802.1X 認証における RADIUS サーバの役割として、最も適切なものはどれか。
正解：イ
RADIUS（RFC 2865）は IETF が規定した独立した規格です。802.1X とは別物であり、VPN・ダイヤルアップ等でも単独で使われます。802.1X はそのフレームワークの中で RADIUS を外部の認証サーバとして呼び出します。
ア：誤り。RADIUS はオーセンティケータと UDP で通信します（サプリカントと直接はやり取りしません）。
ウ：誤り。RADIUS は 802.1X の一部ではなく独立した規格です。
エ：誤り。EAPoL ⇔ RADIUS 変換を行うのはオーセンティケータです。
Q3IEEE 802.1X で利用される EAP 方式の説明として、正しいものはどれか。
正解：イ
PEAP の構造をまとめます：Phase 1（TLS ハンドシェイク：サーバ証明書のみ）→ 暗号化トンネル確立 → Phase 2（MSCHAPv2 等の ID/PW 認証）。
ア：誤り。EAP-TLS はサーバ・クライアント双方の証明書が必要です（相互認証）。
ウ：誤り。EAP-MD5 はサーバ認証がなく、中間者攻撃に脆弱。無線 LAN では使用禁止です。
エ：誤り。EAP-TLS は全端末へのクライアント証明書の発行・管理が必要で PEAP より導入コストが高いです。
Q4IEEE 802.1X 認証後にユーザを所属部門の VLAN に自動割り当てするために、RADIUS の Access-Accept に付加する属性の組み合わせとして正しいものはどれか。
正解：ウ
動的 VLAN 割り当ては属性 64・65・81 の3点セットです。
・Tunnel-Type（属性 64）：値 13 = VLAN を指定
・Tunnel-Medium-Type（属性 65）：値 6 = IEEE 802 を指定
・Tunnel-Private-Group-ID（属性 81）：VLAN ID 文字列（例："100"）
ア の属性は Access-Request（認証要求側）で使われます。イ は EAP パケット搬送・整合性確認用。エ は接続元情報の記録用です。いずれも VLAN 割り当てとは無関係です。
Q5有線 LAN に IEEE 802.1X 認証を導入した環境で、認証済みクライアント PC の後段にリピータハブを接続した場合に生じるリスクとして最も適切なものはどれか。
正解：イ
802.1X の認証はポート単位で行われます。1 ポートが認証済みになると、そのポートに接続されたハブ配下のすべてのデバイスがネットワークにアクセス可能になります。これは 802.1X の根本的な限界の一つです。
対策：MACsec（802.1AE）でフレームレベルの認証・暗号化を行う、または MAC アドレス数制限を設定する。
ウ：誤り。RADIUS 通信は常に UDP/IP ベースです。EAPoL はスイッチまでの区間でのみ使われます。
エ：誤り。標準の 802.1X にそのような自動割り当て機能はありません。
Q6WPA2-Enterprise 環境で EAP-TLS 認証を使用している場合、PEAP（MSCHAPv2）に変更することのデメリットとして最も適切なものはどれか。
正解：ウ
EAP-TLS からPEAPへの変更のデメリットは「パスワード認証への後退」です。
・EAP-TLS：証明書による端末認証。パスワードが存在しない → 辞書攻撃・フィッシング耐性が高い
・PEAP：ID/パスワード認証。パスワード漏洩リスクが生じる。さらにサーバ証明書の検証を無効化すると偽 RADIUS サーバへの接続（MITM 攻撃）が成立し、クレデンシャルを窃取される危険がある
ア：誤り。PEAP でもサーバ証明書は必要です（クライアント証明書が不要になります）。
イ：誤り。これは逆です。クライアント証明書が必要なのは EAP-TLS の方です。
エ：誤り。PEAP は TLS トンネル内で認証を行うため、内部の通信は暗号化されています。

AuthenticatorEAP メッセージを中継するスイッチや AP。RADIUS クライアントとして動作し、判断は認証サーバに委ねる。
RADIUSRFC 2865（IETF）。AAA（認証・認可・アカウンティング）サービスを提供。UDP 1812/1813。802.1X とは独立した規格。
AAAAuthentication（認証）・Authorization（認可）・Accounting（アカウンティング）の略。RADIUS が提供する3機能。
EAP-TLSクライアント・サーバ双方の証明書による相互認証。最もセキュアな EAP 方式（RFC 5216）。
PEAPProtected EAP。外側TLSトンネル（サーバ証明書のみ）＋内側 MSCHAPv2 等の二層構造。Microsoft 環境で主流。
動的 VLANRADIUS Access-Accept の Tunnel 属性（64/65/81）でユーザごとに VLAN を自動割り当てる機能。
Controlled Port認証前はブロック、認証後に開放されるデータ通信用の論理ポート。
Uncontrolled PortEAPoL フレームのみ常時通過を許可する認証専用の論理ポート。
MACsecIEEE 802.1AE。L2 フレームの暗号化・完全性保護（GCM-AES）。802.1X の MKA と連携して鍵交換。
WPA2-EnterpriseIEEE 802.11i のエンタープライズモード。IEEE 802.1X + EAP + CCMP（AES-128）。RADIUS サーバ必須。
4-Way HandshakeWPA2 認証後に PMK から PTK/GTK を生成・交換するプロセス。セッションごとに異なる鍵を確立する。

CoAChange of Authorization（RFC 5176）。認証後にポリシーを動的変更・強制切断する機能。
MABMAC Address Bypass。802.1X 非対応機器に対して MAC アドレスで認証を代替する仕組み。詐称に脆弱。

試験対策 5つの鉄則

1. IEEE 802.1X（IEEE規格）と RADIUS（IETF/RFC 2865）は別々の規格 — 802.1X が外側の枠、RADIUS が判定エンジン
2. オーセンティケータは認証の判断をしない — EAPoL ⇔ RADIUS 変換をするだけ。判断は RADIUS サーバ
3. EAP-TLS = クライアント証明書も必要、PEAP = サーバ証明書のみ必要 — この差が最頻出
4. 動的 VLAN は属性 64・65・81 の3点セット — Tunnel-Type / Tunnel-Medium-Type / Tunnel-Private-Group-ID
5. 802.1X は有線・無線どちらにも適用できる — WPA2/WPA3-Enterprise の認証基盤として利用
