「どの層で動くか」が覚えるべき核心：IPsec は L3（ネットワーク層）で IP パケット自体を保護するため、TCP/UDP や上位のアプリを問わず全通信を自動的に暗号化します。SSL-VPN/TLS は L5〜L6（セッション〜プレゼンテーション層）で動作し、アプリが明示的に TLS を使う必要があります。SSH は L7（アプリケーション層）に最も近い場所で動き、シェルやファイル転送に特化しています。

05

IPsec 詳解 — AH/ESP・モード・SA

IPsec は複数のプロトコルと概念を組み合わせた「セキュリティのフレームワーク」です。たとえ話で言えば、「金庫の仕様書（標準規格）であって、金庫そのものではない」——具体的な錠前（AES等）や施錠手順（IKE）を組み合わせて初めて機能します。

IPsec フレームワークの構成要素
AH
Authentication Header
役割：認証のみ（暗号化なし）
パケットの完全性検証・送信元認証をHMACで行う。データは平文のまま。
プロトコル番号51
NATとの互換性なし（非互換）
NATを通過するとIPヘッダが書き換わりAHの整合性チェックが失敗。現在はほぼESPに置き換えられている。
ESP
Encapsulating Security Payload
役割：暗号化 + 認証（現在の主役）
データを暗号化しつつ、認証も行う。IPsecでほぼ必ずESPが使われる。
プロトコル番号50
NATとの互換性NAT-T で対応
NAT-T (NAT Traversal) でUDPポート4500にカプセル化することでNAT環境でも動作可能。
SA
Security Association
役割：セキュリティの取り決め（契約書）
「どのアルゴリズム・鍵・有効期限で通信するか」の合意。一方向ごとに1つのSAが必要。
識別子SPI（32bit）
3つのSAIKE SA / AH SA / ESP SA
双方向通信には最低2つのSAが必要（送信用・受信用それぞれ）。SADに保存される。

IPsec の3つの SA（Security Association）

IKE SA
IKE SA（ISAKMP SA）：IKE（Internet Key Exchange）の通信自体を保護するためのSA。「鍵交換の鍵を交換するための鍵の取り決め」というメタな存在。IKEフェーズ1で確立される。以降の鍵交換は暗号化された安全な経路で行われる。
AH SA
AH SA：AH プロトコルが使用するSA。認証アルゴリズム（HMAC-SHA等）と鍵を定義する。現在は使用頻度が低い。
ESP SA
ESP SA：ESP プロトコルが使用するSA。暗号アルゴリズム（AES等）・認証アルゴリズム・鍵・SPI を定義する。IKEフェーズ2で確立される。実際のデータ暗号化通信に使用される。

モードの違い（トンネルモード vs トランスポートモード）

比較項目トンネルモードトランスポートモード
元のIPヘッダ暗号化される（新IPヘッダを追加）そのまま残る（平文）
主な用途拠点間VPN（サイト間VPN）ホスト間の直接暗号化通信
両端の装置VPNゲートウェイ（FW/ルータ）エンドホスト（PC同士など）
パケットサイズ大きくなる（新IPヘッダ分）小さい（IPヘッダを追加しない）
試験での頻出度非常に高い（拠点間VPN問題で必ず登場）中程度

SSL-VPN は「TLS（HTTPS）を使ってVPNを実現する」技術です。Port 443 を使うため、ファイアウォールを通過しやすいのが大きな特徴です。アクセス方式は3種類あり、アクセスできるリソースの範囲と、必要なクライアントソフトが異なります。

SSH — Secure Shell の認証方式

SSH はサーバのリモート操作（シェルアクセス）・ファイル転送（SCP/SFTP）・ポートフォワーディングをセキュアに行うプロトコルです。たとえ話で言うと「鍵穴のある防音電話ボックス」——中の会話は外から聞こえず、鍵がないと入れません。

SSH プロトコルの3層構造

接続層
SSH Connection Protocol（L3相当）：暗号化されたチャネル上でシェルセッション・ポートフォワーディング・ファイル転送などの複数チャネルを多重化する。
認証層
SSH User Authentication Protocol（L2相当）：ユーザ認証を行う。パスワード認証・公開鍵認証・GSSAPI認証などを提供する。
転送層
SSH Transport Layer Protocol（L1相当）：サーバ認証・鍵交換（Diffie-Hellman等）・暗号化・整合性確認を提供する。TCP Port 22上で動作。

ドアの前で番号を押す。正しければ入れる。番号が漏れたら誰でも入れてしまう。

ローカル
PF

リモート
PF

ダイナミック

シンクライアント — 端末セキュリティの最終手段

シンクライアント（Thin Client）は「端末にデータを持たせない」という発想のセキュリティアーキテクチャです。たとえ話で言えば「スクリーンとキーボードだけのモニタ」——中身はサーバにあり、端末を盗まれてもデータは取れません。ファットクライアント（通常のPC）の逆の概念です。

シンクライアント 3 方式の比較
サーバベース型
Server Based Computing
たとえ：映画館のスクリーン
映画（処理）は映写機（サーバ）で行われ、席（端末）はスクリーンを見るだけ。
アプリの実行・データ保存を全てサーバ上で行い、端末には画面表示・入力操作のみを送受信する。
RDP / ICA / RFB（VNC）
端末にデータ残留なし
端末スペック低可、ネットワーク依存
ネットブート型
Network Boot
たとえ：図書館の借り本PC
使うたびに本棚（サーバ）から必要なページ（OS）を借りる。使い終わったら返す（変更消去）。
OSや環境をネットワーク経由でサーバからロードして起動する。端末のHDDは使用しないか存在しない。
PXE / iSCSI Boot
起動のたびにクリーンな状態
ネットワーク帯域を消費
ブレードPC型
Blade PC
たとえ：ロッカーに預けたPCを遠隔操作
データセンターのロッカー（シャーシ）に個人のPC（ブレード）を入れ、自宅からリモート接続して使う。
ユーザ専用のPC（ブレード）をデータセンターに設置し、端末からRDP等でリモート操作する。物理PCの遠隔地収容。
RDP / VMware Blast
個別PC環境をセンター集中管理
コスト高（物理PC×人数分）

過去問スタイル 練習問題

Q1IPsec のトンネルモードとトランスポートモードの違いについて最も適切な説明はどれか。
正解：ウ
トンネルモードは元のIPパケット全体（IPヘッダ＋ペイロード）を暗号化し、新しいIPヘッダ（VPNゲートウェイのIPアドレス）を付加します。外部から見えるのはVPNゲートウェイのIPアドレスのみで、内部の通信先IPアドレスは隠蔽されます。拠点間VPN（サイト間VPN）の標準的な使い方です。トランスポートモードはIPヘッダを残したままL4以上を暗号化し、ホスト間の直接暗号化通信に使います。
Q2IPsec の AH（Authentication Header）について正しいものはどれか。
正解：ウ
AH（Authentication Header）は認証（完全性確認・送信元認証）のみを提供し、データの暗号化は行いません。プロトコル番号は51です。NATを通過するとNAT装置がIPヘッダのIPアドレスを書き換えるため、AHが計算した整合性チェック値（HMAC）と一致しなくなり認証失敗します。このためNAT環境ではAHは使えません。現在はESP（プロトコル番号50：暗号化＋認証、NAT-Tで対応）が主流です。
Q3IKE（Internet Key Exchange）のフェーズ1で確立されるのはどれか。
正解：イ
IKEフェーズ1では、IKE SA（ISAKMP SA）が確立されます。これは「IKEの通信自体を保護するための取り決め」であり、以降のフェーズ2のネゴシエーションは、このIKE SAによって保護された安全な経路で行われます。フェーズ2（クイックモード）では、実際のデータ暗号化通信のためのIPsec SA（ESP SA / AH SA）が確立されます。
Q4SSL-VPN のリバースプロキシ方式の説明として正しいものはどれか。
正解：ア
リバースプロキシ方式では、クライアントはブラウザでHTTPS（Port 443）のみでSSL-VPN装置に接続し、VPN装置がプロキシとなって内部Webサーバにアクセスを代行します。HTTPアプリのみに限定されますが、クライアントに専用ソフトが不要です。イはL2フォワーディング方式、ウはポートフォワーディング方式の説明です。
Q5SSH の公開鍵認証の手順として正しいものはどれか。
正解：エ
SSH公開鍵認証の手順は次の通りです。①事前準備：クライアントで鍵ペアを生成し、公開鍵をサーバの~/.ssh/authorized_keysに登録。②接続時：クライアントが公開鍵識別子を送信 → サーバが乱数（チャレンジ）を公開鍵で暗号化して送信 → クライアントが秘密鍵で復号したレスポンスを返送 → サーバが正しい秘密鍵所持を確認してアクセス許可。秘密鍵はネットワーク上を流れないため、ブルートフォース攻撃やパスワード漏洩リスクがありません。
Q6シンクライアントの最大のセキュリティ上のメリットはどれか。
正解：ウ
シンクライアントの最大のセキュリティメリットは「端末にデータを持たない」点です。業務データはサーバ側にのみ存在し、端末上にはデータや業務アプリケーションが保存されません。このため、端末を紛失・盗難されてもデータ漏洩のリスクがほぼゼロになります。また、任意のソフトウェアをインストールできないためマルウェア感染リスクも低減されます。一方、ネットワークに依存するため、ネットワーク障害時には業務が停止するという短所があります（エは逆で誤り）。

重要用語まとめ

試験頻出キーワード

VPNVirtual Private Network。公衆インターネット上に仮想的な専用線トンネルを構築し、安全な通信を実現する技術の総称。
PPTPPoint-to-Point Tunneling Protocol。L2（データリンク層）で動作するVPNプロトコル。MPPE暗号化使用。脆弱性多数で現在は非推奨。TCP 1723 / GRE。
IPsecIP Security。L3（ネットワーク層）でIPパケットの暗号化・認証を行うプロトコルスイート。AH・ESP・IKEで構成される。
AHAuthentication Header。認証（改ざん検知・送信元認証）のみ提供。暗号化なし。プロトコル番号51。NATと非互換。
ESPEncapsulating Security Payload。暗号化＋認証を提供。プロトコル番号50。NAT-TでNAT環境でも動作可能。現在のIPsecの主役。
SASecurity Association。IPsecの通信パラメータ（アルゴリズム・鍵・有効期限）の取り決め。一方向ごとに1つ。SPIで識別。SADに保存。
SPISecurity Parameter Index。SAを識別する32bitの値。IPsecパケットのヘッダに含まれる。
IKEInternet Key Exchange。IPsecの鍵交換プロトコル。フェーズ1（IKE SA確立）・フェーズ2（IPsec SA確立）の2段階。UDP 500を使用。
ISAKMP SAIKEフェーズ1で確立されるSA。IKE通信自体を保護する。以降の鍵交換は暗号化済みチャネルで行われる。
メインモードIKEv1フェーズ1の交渉モード。6メッセージ（3往復）。ID情報を暗号化後に送信するため匿名性が高い。固定IP間の拠点間VPN向け。
アグレッシブモードIKEv1フェーズ1の交渉モード。3メッセージ（高速）。ID情報を平文で送信するため匿名性なし。セキュリティ強度が低い。
クイックモードIKEv1フェーズ2の交渉モード。IKE SAで保護された経路で、IPsec SA（ESP SA）を確立する。
NAT-TNAT Traversal。ESPをUDPポート4500でカプセル化することでNAT環境でもIPsecを使用可能にする仕組み。
トンネルモードIPsecのモード。元のIPパケット全体を暗号化し、新しいIPヘッダを付加する。拠点間VPNの標準。元IPアドレスも隠蔽される。
トランスポートモードIPsecのモード。元のIPヘッダを保持したままL4以上を暗号化する。ホスト間の直接暗号化通信に使用。
SSL-VPNTLS（HTTPS）を利用したVPN。Port 443を使用するためFWを通過しやすい。リバースプロキシ・ポートフォワーディング・L2フォワーディングの3方式がある。
リバースプロキシ方式SSL-VPNの方式の一つ。VPN装置がプロキシとなりHTTPアプリへのアクセスを代行。ブラウザのみで使用可能だがHTTPアプリに限定。
ポートフォワーディング方式SSL-VPNの方式の一つ。クライアント端末の特定ポートをSSLトンネル経由で内部サーバの特定ポートに転送。TCP対応アプリが対象。
L2フォワーディング方式SSL-VPNの方式の一つ。仮想NICで社内L2に接続。全プロトコル対応。専用クライアントが必要。IPsecと同等の使い勝手でPort 443を使用。
SSHSecure Shell。暗号化されたリモートログイン・ファイル転送・ポートフォワーディングを提供。TCP Port 22。
公開鍵認証（SSH）SSHの認証方式。秘密鍵/公開鍵ペアを使用。公開鍵をサーバのauthorized_keysに事前登録。チャレンジレスポンス方式で秘密鍵所持を証明。
パスワード認証（SSH）SSHの認証方式。ユーザ名とパスワードを暗号化経路で送信。設定容易だがブルートフォース攻撃に脆弱。
シンクライアント端末にデータや業務アプリを持たないPC。処理をサーバ側で行う。端末紛失時の情報漏洩リスクを最小化。
サーバベース型シンクライアントの方式。アプリをサーバで実行し、画面表示・入力操作のみを端末に転送。RDP/ICA/VNCを使用。
ネットブート型シンクライアントの方式。OSをネットワーク経由でサーバからロードして起動。PXE/iSCSI Bootを使用。
ブレードPC型シンクライアントの方式。ユーザ専用のブレードPCをデータセンターに集約し、端末からリモート操作する。

試験対策 7つの鉄則

1. IPsec はL3、SSL-VPN/TLS はL5〜7、SSH はL7、PPTP はL2 — 動作レイヤを覚える
2. トンネルモード＝元IPも暗号化（新IPヘッダ追加）、トランスポートモード＝元IPは平文
3. AH（51）＝認証のみ・NATと非互換、ESP（50）＝暗号化＋認証・NAT-Tで対応
4. IKEフェーズ1＝IKE SA（安全な交渉チャネル）、フェーズ2＝IPsec SA（実データ暗号化）
5. メインモード（6メッセージ・安全・固定IP向け）vsアグレッシブモード（3メッセージ・高速・ID平文）
6. SSL-VPN：リバースプロキシ＝ブラウザのみ・HTTPのみ、ポートフォワーディング＝特定TCPポート、L2フォワーディング＝全プロトコル（仮想NIC）
7. シンクライアントの本質＝「端末にデータを持たせない」——紛失・盗難・マルウェアリスクの最小化
