インシデント対応の全体像

インシデント対応とは、セキュリティ事象が発生したときに組織が取るべき準備・検知・対処・回復・教訓化の一連の活動。試験では「何を、誰が、いつ、どの順で」が問われる。

「事象」と「インシデント」の区別

イベント (Event)

「FWのログにポートスキャンが記録された」「ファイアウォールが1件遮断した」

→ 単なるログレコード。意味付けはまだない

インシデント (Incident)

「ポートスキャンを足がかりに侵入された」「マルウェアが実行され横展開した」

→ 業務・情報資産・組織に実害もしくは具体的脅威を与えた事象

イベント全件をインシデント扱いすると現場が回らないため、トリアージ（優先度判定）でインシデント認定し、対応リソースを集中させる。

NIST SP 800-61 — 6段階フレームワーク

米国NISTが策定したComputer Security Incident Handling Guide。世界標準。日本のJPCERT/CC、IPA、防衛省・金融庁ガイドラインも基本的にこのフレームに準拠している。

6つのフェーズ

1準備
2検知・分析
3封じ込め
4根絶
5復旧
6事後対応
1. 準備（Preparation）
平時の体制整備。CSIRT組成・連絡網・対応手順書・分析環境（フォレンジックキット、サンドボックス）の整備、訓練、外部委託先との契約、ログ保全方針。インシデント発生前にすべて固めておく。
2. 検知・分析（Detection & Analysis）
SIEM・IDS・利用者通報からのインシデント候補を検知し、真陽性／偽陽性を判定。スコープ（影響範囲）、深刻度、攻撃者動機を分析。誤検知を含めて記録し、後の改善に活かす。
3. 封じ込め（Containment）
被害拡大を止める応急処置。感染端末の隔離（LANから切断）、不正アカウントの停止、攻撃元IPの遮断、悪用された機能の一時停止。「観察を続けるべきか、即時遮断すべきか」が判断ポイント。
4. 根絶（Eradication）
原因（マルウェア、設定不備、脆弱性、不正アカウント）を完全除去。OS再構築、パッチ適用、認証情報リセット、攻撃者のバックドア除去。封じ込めだけでは再侵入される。
5. 復旧（Recovery）
システムを正常運用に戻す。段階的復旧、監視強化、ベースライン比較。すぐに本番投入せず一定期間の監視期間を設けるのが安全策。
6. 事後対応（Post-Incident Activity）
振り返り会（Post-Mortem）を実施。原因分析報告書、再発防止策、訓練・手順書の更新、ステークホルダ報告。教訓を組織知として残す。

CSIRTとJPCERT/CCの役割

CSIRTの種類

CSIRT（Computer Security Incident Response Team）は組織形態で次のように分類される。

① 内部CSIRT
企業の自社CSIRT。従業員・自社システムを対象。NTT-CERT、日立CSIRT等。
② コーディネーションCSIRT
業界・国レベルで横断的調整。JPCERT/CC、ISAC（金融、自動車、電力等）。複数組織間の情報共有が役割。
③ 分析CSIRT
マルウェア解析・脆弱性研究を専門に行うCSIRT。研究機関・セキュリティベンダ。
④ ベンダCSIRT
製品ベンダの製品セキュリティ専門CSIRT（PSIRT）。Microsoft MSRC、Cisco PSIRT等。

JPCERT/CCの役割

日本のコーディネーションCSIRTの中核。一般社団法人JPCERTコーディネーションセンター。

機能具体的活動
インシデント対応支援国内組織からの相談受付・調整
脆弱性情報ハンドリングJVN（IPA共同運営）で公表、関係者への連絡
注意喚起・早期警戒注意喚起 / Weekly Report 発行
国際連携FIRST加盟、海外CERT連携

連絡先と窓口

JPCERT/CC連絡：info@jpcert.or.jp または専用フォーム。インシデント報告はir@jpcert.or.jp。攻撃元IPの管理者特定（whois経由）、海外CSIRTとの連携依頼などを無料で支援してもらえる。

R4秋 PM2問2 旧過去問より — IRチームの体制設計
旧形式の長文総合問題で、CSIRTの体制設計と運用プロセスが問われた。論点は：①常設チーム vs バーチャルチームの選択基準、②SOC（24/7監視）とCSIRT（事後対応）の役割分担、③FIRSTやNCAなどの外部コミュニティへの加盟意義、④インシデントの種別ごとに事前定義したエスカレーション基準の重要性。新形式R6秋問1でも体制設計の話は登場しており、ここで定着させた知識は流用できる。「事前合意」「24/7」「演習・訓練」がキーワード。

初動対応の判断 — 「観察」か「遮断」か

侵入を確認した瞬間、運用者は2つの選択肢に直面する。

① 即時遮断（agressive）

該当端末をLANから切断、攻撃元IP遮断、機能停止。

長所：被害拡大を即座に止められる。

短所：攻撃者が察知し痕跡消去・別ルート確保に動く。事後分析で全容把握困難。

② 観察継続（passive）

通信を監視しつつ、攻撃の全体像を把握してから一網打尽に対応。

長所：攻撃者のC2先・道具・目的を解明できる。

短所：観察中に追加被害が発生するリスク。法的・倫理的判断が要る。

判断基準：金銭被害・人命・個人情報漏えいの恐れがある場合は即時遮断。それ以外で侵入直後・偵察段階とみられる場合は、CSIRTで合意の上、限定的な観察もあり得る。観察続行する場合も、業務影響の少ない迂回経路を用意する。

R3秋 PM2問2 旧過去問より — マルウェア感染端末への対処手順
旧形式時代の頻出シナリオ。マルウェア感染の疑いがある端末に対し、現場担当者が「すぐ電源を落として再起動した」ケースが繰り返し問われている。採点ポイントは2つ：①電源断＝メモリ上の揮発性情報が失われる（マルウェアプロセス・復号鍵・C2接続情報など）、②論理隔離＝攻撃通信の遮断と調査通信の維持の両立。新形式R6秋問1でも同種設問が再登場しており、旧過去問演習が直接効く領域。記述では「メモリ／プロセス／ネットワーク接続情報の喪失」を必ず明記すること。
5

フォレンジック — 証拠保全の作法

事後調査のために、ディスク・メモリ・ログ等の証拠を原状を変えずに保全する技術。法的訴追の可能性がある場合は法廷で通用する手続きが必要。

証拠保全の順序（揮発性順）

消えやすい情報から先に保全する。これは試験頻出。

1
CPU・レジスタ・キャッシュ　最も揮発性が高い。稼働中のメモリダンプで取得。電源を切ると失われる。
2
メモリ（RAM）　実行中プロセス・ネットワーク接続・暗号鍵が含まれる。専用ツール（Volatility、FTK Imager Live）で取得。
3
ネットワーク状態　接続中のセッション、ARPテーブル、ルーティングテーブル、開いているポート。
4
稼働中プロセス・ファイル　稼働中プロセスID、開いているファイルハンドル。
5
ディスク（永続）　シャットダウン後、ハードウェア書込み禁止装置（write blocker）経由でディスクをイメージ取得。dd / EnCase / FTK等。
6
外部ログ　既にSIEM・Syslogに転送済みのログ。比較的安全。

Chain of Custody（証拠管理の連鎖）

誰が・いつ・どこで・どうやって取得し、その後誰が保管したかの記録の連鎖。途切れると法廷で証拠採用されない。

記録項目例
取得日時2025-XX-XX 14:30:00 JST
取得者○○氏（CSIRT）+ △△氏（証人）
取得場所東京本社サーバルーム ラック#3
対象サーバA HDD ＃1（型番：xxx、シリアル：xxx）
方法Write Blocker経由でddコマンドにてビット単位コピー
ハッシュ値SHA-256: a1b2c3...（取得直後・封印時の2回計算で改ざんなしを担保）
保管経路取得→封印→金庫（鍵管理者○○）→分析者へ受渡し時に記録更新
R7春午前Ⅱ問15で出題：「証拠保全の順番」。揮発性が高い順（メモリ→ネットワーク状態→稼働プロセス→ディスク→外部ログ）が正解。
H31春 PM2問1 / R元秋 PM1問3 旧過去問より — 標的型攻撃 / DNSトンネリング
古典の旧形式から繰り返し出題された標的型攻撃シナリオ。論点：①初期侵入＝メール添付ファイルや水飲み場攻撃でマルウェア感染、②内部探索・横展開＝Pass-the-Hash等で他PCへ拡散、③情報持出＝DNSトンネリングでC2サーバへ少量ずつ流出。採点ポイントの中核は「ライブメモリ取得」＝暗号化ディスクの復号鍵・C2接続情報・マルウェアプロセス実体はメモリにしか存在しないため、電源切断より優先する。Order of Volatility原則として20回中13回以上で問われ続けている不変論点。第14章Q44/Q47参照。
H29秋 PM1問1 / H29春 PM1問1 旧過去問より — ランサムウェアと初動報告フロー（黎明期の経典）
WannaCry/NotPetya時代（2017年）の出題。H29秋ではランサム被害最小化として3-2-1バックアップルール（コピー3つ／媒体2種以上／1つは隔離保管）が問われた。常時オンラインのバックアップは感染時に同時暗号化されるため、オフライン媒体やイミュータブルストレージでの保管が必須。H29春では初動報告フローが論点で、影響度トリアージ基準の文書化とIRT直通の24/7対応窓口がポイント。両者とも現代のRansomOps時代でも通用する原則。第14章Q51/Q55参照。

法定報告と外部連絡

個人情報・金融・電気通信などの分野では、インシデント発生時に所管官庁等への報告義務がある。

主要な法定報告

規制対象期限報告先
個人情報保護法個人データ漏えい等速やかに（暫定）→30日以内（確報）個人情報保護委員会・本人
個情法 + 不正アクセス絡み不正利用された情報3〜5日以内（暫定）→60日以内（確報）同上
GDPR（EU）EU市民データ漏えい72時間以内監督機関 + データ主体

「72時間ルール」の覚え方

GDPRが72時間。日本の個情法（不正アクセス絡み）は3〜5日。「事故を知ってから3日以内に第一報」を内部ルールにしておけば、ほぼ全規制をカバーできる。

注意：72時間ルールは「全容判明後72時間」ではなく「認識後72時間」。詳細不明でも「不明」と書いて第一報を出すのが正解。確報は後日改めて出す。

過去問記述演習

演習1初動対応の妥当性（R6秋問1類題）
『A社のWebサーバが不正アクセスを受けた疑いが10:00に検出された。運用者Rは攻撃元IPのFW遮断を11:00に実施したが、CSIRT責任者への報告は翌日09:00であった。被害調査の結果、夜間に内部DBへの不正アクセスが拡大していたことが判明した。』
設問：Rの初動対応の問題点と改善策をそれぞれ述べよ。
解答例：
問題点：CSIRT責任者への報告が翌日まで行われず、夜間の追加被害を検知できなかった。
改善策：インシデント検知時には対処と並行して、定められた連絡網に従い直ちにCSIRT責任者に報告する。
演習2証拠保全の順序
マルウェア感染が疑われるサーバから証拠保全を行う際、(ア)ディスクイメージ、(イ)メモリダンプ、(ウ)ネットワーク接続情報、(エ)外部SIEMログ の取得順序として最適なものを述べ、その理由も簡潔に示せ。
解答例：(イ)メモリダンプ → (ウ)ネットワーク接続情報 → (ア)ディスクイメージ → (エ)外部SIEMログ。理由は、揮発性が高い情報ほど消えやすいため先に保全する必要があり、稼働中のメモリ・ネットワーク状態を最優先する。
本章のまとめ

① NIST 6段階（準備→検知分析→封じ込め→根絶→復旧→事後対応）。② CSIRTは内部・コーディネーション・分析・ベンダの4種、JPCERT/CCはコーディネーション中核。③ 初動は遮断と観察のトレードオフ、即時被害があれば遮断優先。④ 証拠保全は揮発性順、Chain of Custodyを記録。⑤ 72時間以内の第一報を内部ルール化。
