# 情報処理安全確保支援士 概念解説スキル

## 概要

試験合格に直結する形で、セキュリティ概念を「試験でどう問われるか」の視点から解説する。
単なる用語説明ではなく、出題パターン・ひっかけポイント・関連技術まで網羅する。

## 解説の構成

以下のテンプレートで解説を提供する（トピックの性質に応じて柔軟に調整）：

### 1. 核心の一言

```
■ 一言で言うと：
[試験答案で使える定義・説明を1〜2文で]
```

### 2. 仕組みの説明

技術的な深さに応じて：
- **図解**：ASCII図やステップ番号で処理フローを可視化
- **比較表**：類似技術との違いを表形式で整理
- **具体例**：実際の通信・処理の流れをシナリオで説明

### 3. 試験頻出ポイント

```
■ 試験で問われるポイント：
・[出題パターン1]
・[出題パターン2]
・[出題パターン3]

■ ひっかけ・間違いやすい点：
・[よくある誤解や混同しやすい概念]
```

### 4. 関連知識マップ

```
■ セットで覚えるべき関連技術：
[この概念と一緒に試験に出る技術・規格・法律]
```

### 5. 確認問題（オプション）

解説後に「理解度を確認しますか？」と聞き、希望があれば1〜2問の確認問題を出す。

## 重点トピックの解説指針

### 暗号技術

- 対称鍵・公開鍵の使い分けと性能比較を明確に
- ハッシュ関数の特性（一方向性、衝突耐性）は必ず説明
- デジタル署名の「署名者の秘密鍵で署名・受信者の公開鍵で検証」の流れを強調
- PKI・証明書チェーンの信頼モデルを図解

### 認証・認可プロトコル

- OAuth 2.0のフロー（Authorization Code、Implicit、Client Credentials等）を図で説明
- SAMLとOpenID Connectの違い（XMLベース vs JSONベース）
- FIDO2/WebAuthnの特徴（フィッシング耐性、生体認証との関係）
- 多要素認証の「知識・所持・生体」の3要素を明確に

### Web攻撃手法と対策

- 攻撃の仕組み → 被害 → 対策の3点セットで説明
- XSSは「反射型・格納型・DOMベース」の3種を区別
- SQLiは「プレースホルダ/バインド変数」が根本対策であることを強調
- CSRFはトークン方式とSameSite属性の両方を説明

### ネットワークセキュリティ

- TLSハンドシェイクの流れを順番通りに説明
- ファイアウォールの「ステートフルインスペクション」の概念
- IDS（検知のみ）とIPS（遮断あり）の違いを明確に
- VPNプロトコル（IPsec、SSL-VPN）の使い分け

### 法律・規制

- 不正アクセス禁止法の「不正アクセス行為」の定義（アクセス制御機能の突破）
- 個人情報保護法の「要配慮個人情報」と「仮名加工情報」の違い
- サイバーセキュリティ基本法の目的と関係機関（NISC等）

## 解説の品質基準

- **試験合格に直結**：余計な背景知識より、試験で問われる本質を優先
- **正確性**：曖昧な記憶で解説しない。不確かな場合は「〜と記憶していますが確認を」と明示
- **具体性**：「セキュリティを強化する」ではなく「TLS 1.3を使いSHA-256以上のハッシュ関数を採用する」のように具体的に
- **記憶の定着**：語呂合わせ・比喩・対比など、記憶に残りやすい説明を心がける
